# متابعة المعاينات — 17 نوفمبر 2026

## ما ثبت على LIVE

- React: ظهور الصفحة والعداد وإعادة التعيين والتحديث في مشروع الاختبار.
- الإيقاف من الواجهة يزيل الإطار ويعطل أزرار المعاينة. إعادة التشغيل تعيد الصفحة.
- تبديل مشروع المعاينة إلى Python ثم العودة إلى React يعرض المشروع المحدد.
- دُمج إصلاح #52 ونشر عبر العملية react_activate في تشغيل Actions رقم 44040598727؛ نجح اختبار العامل. فحص انتهاء المهلة عند القراءة نفسه يمنع نافذة الانتظار بين دورات التنظيف.
- أوقفت المعاينات المستخدمة بعد الاختبار لتحرير الموارد.

هذه النتائج لا تثبت العزل بين حسابين ولا عزل أدوات وكيل Pi. الفحوص السابقة للموارد وعزل العامل مستقلة عن فحص حدود حساب العميل.

## إضافة Java — جاهزة للاختبار على الخادم

- ملف Main.java في جذر المشروع، يستخدم Java 21 دون مكتبات خارجية ويقدم HTTP على المنفذ 8080 داخل الحاوية فقط.
- نفس العامل الحالي والتفويض والروابط المؤقتة وحدود الذاكرة 768 MiB والمعالج 0.5 ونوع الشبكة none والمصدر للقراءة فقط.
- حد ذاكرة JVM للتطبيق 256 MiB، ووسيط القراءة المحلي 32 MiB. وسيط القراءة ملف موثوق مترجم داخل الصورة، وليس شفرة مأخوذة من المشروع.
- لا دعم تلقائي لمشاريع Maven أو Gradle أو تطبيقات سطح المكتب في هذه المرحلة. وجود pom.xml وحده لا يسمح بتشغيل أمر بناء عشوائي.
- صورة التشغيل مبنية من صورة eclipse-temurin الرسمية بعد تثبيت مرجع digest. لا تثبيت اعتماديات من مشروع عميل ولا تغيير للشبكة.
- العملية java_activate ترفض العمل عند وجود معاينة ديناميكية نشطة، وتتحقق من احتياطي القرص. تحتفظ بنسخة من الملفات وإعداد العامل وتعيدهما إذا فشل الاختبار.
- الأثر: إعادة تشغيل العامل وGateway، دون إعادة تشغيل Docker أو Pi، ودون تعديل قاعدة البيانات أو Nginx.

## المتبقي

1. إثبات تشغيل Java فعليًا داخل الحاوية ثم واجهة العميل؛ اختبارات المصدر لا تعوض هذا الإثبات.
2. إعداد وبناء React عند الطلب داخل عزل محدود، مع تنزيل اعتماديات مضبوط وتخزين مؤقت معزول. لا يفتح تنزيل الحزم شبكة تنفيذ التطبيق.
3. اختبار حسابين فعليين بمعرفات وملفات canary فقط، بما في ذلك الروابط المنتهية والقديمة بعد الإيقاف.
4. مراجعة عزل أدوات Pi وفق مذكرة الحماية؛ لم تعالجه تغييرات المعاينات.
