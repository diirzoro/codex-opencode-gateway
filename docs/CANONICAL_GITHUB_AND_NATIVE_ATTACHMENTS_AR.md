# سياسة GitHub والمرفقات: الصلاحيات والتنفيذ والحالة
هذا المستند مرجع واحد للعمليتين. القرار المعماري الأعلى في [Native First](CANONICAL_NATIVE_FIRST_ARCHITECTURE_AR.md)، وفحوص السيرفر في [TEST Status](CANONICAL_TEST_SERVER_STATUS_AR.md).

## GitHub
- GitHub OAuth وربط المستودعات والهوية والتوكنات والتدقيق من مسؤولية Python Control Plane، **وليس** خدمة دردشة Native ولا محركًا بديلًا لـOpenCode.
- كل Connect/Reconnect: OAuth رسمي مع state مرتبط بالجلسة، إثبات معرّف GitHub الرقمي، رفض هوية متصلة بمستخدم Gateway آخر، إدخال العميل لبريده الأساسي من GitHub ومقارنته ببيان primary+verified، ثم رمز OTP للبريد الصحيح، وأخيرًا التأكيد على الهوية والتثبيت. لا استثناء عند أول ربط.
- البيانات الحساسة لا تُعرض في السجلات أو المتصفح. سجل هوية GitHub داخل PostgreSQL القائم يحوي المعرّف الرقمي وبصمة HMAC، لا كلمات السر والتوكنات. لا مخزن حسابات موازٍ.
- Disconnect لا يحذف الملفات أو محادثات Native. حذف نسخة محلية مختارة لا يتم إلا بتأكيد المستخدم، وCommit/Push وتحقق من SHA البعيد، وفحص عدم وجود تعديلات غير محفوظة. لا تمس مستودعات مستخدم آخر.
- أي اتصال Legacy مجهول الملكية يفشل مغلقًا؛ تجوز استعادة رقم مستخدم GitHub من توكنه الموثوق أو من بيانات تثبيته الشخصي المثبتة بواسطة GitHub App نفسه. لا اعتماد على اسم المستخدم أو البريد كبديل للمعرف الرقمي.

## مرفقات المحادثة
- Gateway يتحقق من حساب العميل وملكية Workspace والجلسة ومساحة التخزين، ويستقبل النقل المؤقت المشروط بحجم محدود؛ هذا **ليس** محرك AI أو أداة قراءة النموذج.
- بعد اكتمال النقل، تستخدم رسالة Native الأصلية FilePart للوصول إلى الملف المملوك؛ القراءة والأدوات والردود وSSE تخص OpenCode Native وحده.
- Python لا يستقبل استجابات AI ولا يمرر SSE ثانية. بعد التفويض `X-Accel-Redirect` تنقل Nginx إلى Native وتعيد الرد للعميل مباشرة.
- يدعم النقل إلغاء حقيقيًا، وتنظيف الملفات المؤقتة فقط مع حماية ملفات المشاريع والمحادثات النشطة. لا حفظ موازي لتاريخ المحادثات، ولا إعادة إرسال prompt تلقائيًا عند فقدان ACK.
- فحص الحصة ضروري لكن لا يُعاد مسح شجرة الملفات مرتين لنفس قرار إنشاء المرفق.
- **قرار المالك الجديد في 29 أكتوبر 2026:** OpenCode Native نفسه يقرر إمكانيات قراءة نوع الملف وحدود الملف/النموذج، وليس قائمة Python MIME/extension أو حد 20MiB مستقل. تظل حصة التخزين العامة ومسار النقل الآمن وفحص ملكية الملفات من مهام Gateway، ولا تُفسّر على أنها تحديد لقدرات النموذج. نقل البايتات ليس قراءة AI ولا استخراج مستندات.
- **فحص الفيروسات:** طلب المالك أن يكتفي Python بحماية الملف من الفيروسات/الاستغلال. فحص الملكية والمسارات وعدم التنفيذ ليسا بديلًا عن محرك فحص برمجيات خبيثة؛ لم يُثبت وجود ماسح موثوق في TEST، لذا لا تُعلن الملفات مفحوصة أو آمنة قبل إثبات الفحص دون خدمة AI/قراءة محتوى موازية.
- **المرفقات بعد الاستهلاك:** الرفع المؤقت يمرّ عبر Gateway كناقلة موثقة ولا يضيف أي محرّك محادثة؛ يبقى Native هو من يقرأ ويحكم على النوع. لا تُحذف البايتات قبل أن يتوقف Native نهائيًا؛ الصيانة الحالية تتحقق من idle ووجود إيصال تسليم، وتزيل المرفقات الموقتة بعد مهلة أمان قصيرة حتى لو لم يتمكن النموذج من قراءة التنسيق. عند إيصال غامض أو Native غير متاح تُحفظ الملفات حتى انتهاء TTL أو التحقق؛ منع فقدان ملف ما زال يقرأه Native أعلى أولوية من الحذف الفوري.
- **24 ساعة دون نشاط:** وافق المالك صراحة على محو سجل المحادثات بعد 24 ساعة من آخر نشاط. استُخدم أمر OpenCode الأصلي `DELETE /session/{id}`، من حلقة الصيانة القائمة، بدل مكتبة Python تحفظ/تحذف رسائل AI بنفسها. يفشل التنفيذ مغلقًا عند غياب تحديث الوقت أو اختلاف ownership أو نشاط Native أو عدم تأكيد أمر الحذف. بعد تأكيد Native تحذف Gateway خريطة الجلسة والـreceipts والمرفقات المؤقتة الخاصة بها فقط؛ ملفات المشاريع وGitHub تبقى خارج نطاق الحذف. **هذه إصلاحات مصدر واختبارات تركيبية، وليست إثبات نشر/قبول TEST**.
- لا تُوسّع سياسات الحذف إلى cache المشروع أو تاريخ GitHub أو ملفات العملاء؛ للمشروع سياسة احتفاظ منفصلة. يجب اختبار مستخدمين ومحادثة قديمة/حديثة ونشاط جارٍ قبل نشر TEST.

## إصلاحات المصدر وحالة القبول
- Source `updates`: GitHub legacy verified-installation fallback في `backend/app/services/github.py`؛ يحافظ على الرفض إذا تعذر إثبات الهوية أو تحقق من App مختلف.
- Source `updates`: إزالة traversal مكرر عند إنشاء المرفق في `backend/app/services/chat_attachments.py`.
- اختبارات الانحدار المصدرية أُضيفت، **ولكن لم يُشغّل هذا العمل pytest أو ينشر TEST، ولذلك النتيجة التشغيلية BLOCKED**. وجود جدول `github_identity_registry` المثبت من استعلام المالك لا يعني وحده جاهزية جميع أعمدته أو خدمات البريد أو callback.
- قبل PASS: تحقق من Alembic/schema وcallback/category على TEST، واختبر حسابين مستقلين وOTP حقيقيًا، وارفع ملفًا بمراحل وألغِه، وتأكد من قراءة Native للملف ونجاح رد SSE. لا تعديل LIVE/master/ports/services.
