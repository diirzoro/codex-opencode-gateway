الحالة العامة: **غير جاهز للإنتاج**. هذه جولة إصلاح سبب التعليق المثبت وتوثيق ما تبقى، وليست تنفيذًا للميزات المعمارية المؤجلة. العمل على `updates` فقط، انطلاقًا من `f9a9d553d4ba002f90e71320a1481b232c6ce1dd`. يضاف SHA الإصلاح المنشور في تحديث التوثيق التالي مباشرة.

## نتيجة التشخيص

أصبح اختبار المتصفح مع FastAPI وOpenCode الفعليين ينجح في البيئة المؤقتة. قبل الإصلاح بقي طلب `/api/opencode/catalog/providers` بلا استجابة طوال مهلة 45 ثانية. بعد الإصلاح عاد **HTTP 200 خلال 3773.09 ms** بحسب سجل الخادم، و3777 ms بحسب المتصفح. تحميل خيارات مصادقة OpenAI عاد **HTTP 200 خلال 3518.01 ms**.

المسار الذي تتبعناه:

1. `management.js` يطلب كتالوج الحساب بعد الدخول إلى Connections.
2. FastAPI يتحقق من الجلسة والمستخدم؛ تبقى معاملة الطلب مفتوحة.
3. `for_account` يبدأ runtime خاصًا بذلك المستخدم.
4. بدء runtime كان يفتح جلسة قاعدة بيانات إضافية لقراءة السياسة، ثم جلسة إضافية لاستعادة المفاتيح.
5. جسر PGlite يثبت الاتصال النشط طوال المعاملة. الاتصال الثاني ينتظر انتهاء الأولى، بينما الأولى تنتظر اكتمال بدء runtime.

الدليل قبل الإصلاح: سجل الخادم يصل إلى `for_account.begin` ثم `for_workspace.begin`، دون وصول إلى طلب OpenCode. لم توجد أخطاء JavaScript غير معالجة. اختبار منفصل باتصالين، دون التطبيق أو OpenCode، أثبت أن `SELECT 2` ينتظر معاملة اتصال أول ينفذ `SELECT 1`، ثم يكتمل مباشرة بعد rollback للأول؛ الزمن المقاس 503 ms، منها انتظار مقصود قدره 500 ms.

هذا يثبت **تفاعل الاتصال المتداخل مع قيد PGlite**. لا يثبت وجود قفل PostgreSQL أصلي على صفوف العملاء أو خلل في مزوّد مدفوع. واختبار QueuePool باتصال واحد يثبت أيضًا أن الاتصالات المتداخلة قد تستنفد المجمع؛ SQLite هنا مجرد أداة لاختبار ملكية الاتصال، وليس بديلًا لاختبارات PostgreSQL.

## الإصلاح المحدود

- أضيف معامل `db` اختياري إلى بدء runtime واستعادة مفاتيحه. مسارات HTTP تمرر جلسة الطلب الموجودة لقراءة السياسة والمفاتيح.
- لا يغلق runtime جلسة الطلب، ولا ينفذ commit أو rollback لها. مسارات التشغيل المستقلة تستمر في فتح جلساتها وإغلاقها كما كانت.
- مررنا الجلسة في كتالوج الحساب والبحث والوكلاء وبدء OAuth، ومسارات بدء runtime للمساحات والجلسات والوكيل التي كانت تحمل معاملة قائمة. لم تتغير قرارات الموافقة أو إرسال الرسائل أو المصادقة أو التشفير أو حدود الملكية.
- أضيف اختبار لكتالوج حساب بارد تمامًا دون مشروع، واختبارات لاستعادة المفاتيح باتصال واحد، وملكية المعاملة، وتمرير جلسة المستخدم.
- أدوات التتبع تعمل في تطبيق الاختبار المؤقت فقط. تحفظ اسم العملية والجدول والتوقيت وحالة HTTP؛ لا تحفظ كلمات المرور أو SQL parameters أو cookies أو tokens أو أجسام طلبات المصادقة أو query strings.

### قيود البيئة المطلوبة للخطوة التالية

- لا يوجد `postgres` أو `initdb` أو Docker/Podman أو Docker socket؛ الخريطة المتاحة لمستخدمي النظام تحتوي UID 0 فقط. لذلك **PostgreSQL الأصلي والحاويات محجوبان في البيئة الحالية**. لم نستخدم قاعدة الإنتاج بديلًا.
- لا توجد بيانات sandbox مصرح بها لهذه الجولة لمزوّد نموذج/OAuth أو SMTP خارجي. اختبارات هذه الاتصالات لا تُعتبر مكتملة لمجرد توفر الكود.
- تجربة المدفوعات الخارجية لم تُنفذ، ولم تُقرأ أو تتغير مفاتيح PayPal الإنتاجية أو إعدادات الخادم.
- حذف المشروع الدائم ما زال يرجع 409 ويعرض الأرشفة. الاختبار يزيل مؤقتًا دليل مشروع تجريبي جديد فقط؛ لا يثبت رحلة الحذف الدائم.

لن نغير هذه القيود أو ندمج إلى `master` أو نعيد تشغيل VPS أو نطبق migrations على الإنتاج ضمن هذه الجولة. تبقى مذكرة المشروع المرجع الأساسي، وهذا التقرير يوضح التشخيص وخطة الإغلاق لكل مرحلة.
