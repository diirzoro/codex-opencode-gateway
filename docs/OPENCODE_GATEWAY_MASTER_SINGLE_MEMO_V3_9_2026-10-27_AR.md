# OpenCode Gateway — فهرس القرارات الحالية فقط

**هذا الملف لم يعد مرجع تعليمات منفصلًا أو سجلًا تاريخيًا.** أزيلت منه النصوص المتداخلة والتعليمات القديمة. المرجع المعماري الفعلي هو [CANONICAL_NATIVE_FIRST_ARCHITECTURE_AR.md](CANONICAL_NATIVE_FIRST_ARCHITECTURE_AR.md). أي تاريخ تغييرات سابق يمكن قراءته من Git history، **ولا يُطبّق على المنتج الحالي**.

## النطاق الملزم
- التغييرات على فرع `updates` وTEST فقط، دون مساس بـLIVE أو `master` أو منافذ الخدمات أو الأسرار أو ملفات العملاء.
- **لا خدمات AI موازية لـOpenCode Native** ولا عملية لكل Workspace ولا تخزين مستقل لتاريخ المحادثات والنماذج.
- **كل طلب محمي قد يمر بـPython** للتحقق من المستخدم وملكيته وصلاحياته؛ ثم Nginx internal redirect إلى OpenCode. **رد OpenCode وSSE يذهبان مباشرة من Native عبر Nginx إلى العميل، لا يعودان إلى Python مطلقًا.**
- Python يتحكم في الحسابات وملكية المشاريع والاشتراكات والحصة والهوية وGitHub ورفع النقل المؤقت المصرح. Native وحده يشغّل النماذج والمزودين والرسائل والأدوات والملفات أثناء جلسة المحادثة وSSE. لا تفتح Native مباشرة للعامة أو تعرض أسرار الخدمة.
- الحماية ضد ملفات/مفاتيح حساب آخر وعزل نظام التشغيل ضرورية؛ لا يجوز تعطيل التحقق الأمني لإخفاء 409 أو إصلاح التأخير.
- الإصلاحات لا تمس سجل Native ولا تعيد إرسال طلب غير مؤكد تلقائيًا، ولا تحذف ملفات مشاريع أو تغييرات GitHub لم تُحفَظ.

## المراجع المتخصصة غير المتداخلة
1. [المعمارية النهائية Native First](CANONICAL_NATIVE_FIRST_ARCHITECTURE_AR.md) — المسارات والحدود والمسؤوليات، وهي المرجع الأعلى لكل تغيير معماري.
2. [حالة السيرفر والفحوصات](CANONICAL_TEST_SERVER_STATUS_AR.md) — حالة خدمات TEST ونتائج وأخطاء 409 وقياسات CPU/RAM/SSE والنشر.
3. [GitHub والمرفقات](CANONICAL_GITHUB_AND_NATIVE_ATTACHMENTS_AR.md) — OAuth/OTP والملكية ورفع الملفات المؤقت والـFilePart والتنظيف.

## حالة الإصلاح الحالية، ليست قبولًا للسيرفر
- يوجد `github_identity_registry` وفق استعلام المالك `to_regclass`؛ لم يُثبت فحص الأعمدة أو ترحيل Alembic أو اتصال OTP الحقيقي.
- أُصلح في مصدر `updates` مسار تحقق ملكية GitHub القديمة حين انتهى توكن المستخدم، عبر بيانات التثبيت الشخصي الموقعة من GitHub App مع التحقق من المعرف الرقمي والـApp؛ تبقى الحالات غير الموثوقة **BLOCKED**، ولا تُحذف سجلات العملاء.
- أُزيل فحص quota مكرر عند إنشاء Slot المرفق. Backend يظل مسؤولًا عن تأمين النقل المبدئي، وNative عن FilePart/قراءة الملفات والأدوات والرد. لم تُثبت نتيجة رفع ملف حقيقي على TEST بعد.
- أخطاء 409 في السجلات لا تثبت سببًا وحيدًا؛ يجب الحصول على body/status الحقيقي دون تخمين أو حذف مجلدات.
- تصحيح `prompt_async` في مصدر `e1fa147bfe77` لا يُعتبر منشورًا أو PASS دون deployed SHA واختبارات حية. لا تنشر ملفات Backend وFrontend متعارضة.
- مصدر GitHub/اختبارات محلية لا يساوي نجاح TEST؛ لا تعلن اكتمال التصحيح حتى تحقق قبول مستخدمين منفصلين، ربط GitHub/OTP، نقل ملف وإلغائه، Native FilePart، رسائل وسجل وSSE وRecover.

## إدارة المستندات من الآن
الملاحظات القديمة أو إرشادات per-workspace runtimes أو Python AI proxy أو `Native → Python → Client` ممنوعة. **لا تُعاد إضافتها أو تنفيذها حتى لو وُجدت في نسخ قديمة أو Git history.** لكل مجال مرجع واحد، ولا تُخلط نتائج سيرفر قابلة للتغير مع سياسة نظام ثابتة. أي تعديل يراجع المرجع المتخصص فقط، مع commit واختبار مثبتين.
