# OpenCode Gateway — المذكرة المعمارية والتنفيذية الوحيدة

> **القاعدة الملزمة:** OpenCode Native هو صاحب القرار والتنفيذ والتخزين والتحقق في **كل خدمة تخص OpenCode** دون استثناء. تتصل الواجهة بخدماته مباشرة عبر Nginx. لا تُنشأ طبقة إضافية لإدارة مزوديه أو نماذجه أو وكلائه أو جلساته أو رسائله أو أدواته أو أحداثه، ولا تتوسط الخدمات الإدارية في أي طلب OpenCode، ولو للفحص أو التفويض أو قراءة الحالة.
>
> **لا استثناءات ولا حلول نصفية.** لا يُعد الفصل مكتملًا إذا كانت أي خدمة OpenCode تتوقف على استدعاء خدمة إدارية قبل تشغيلها. الحماية والعزل الإجباريان يجب أن يتحققا عند نقطة الوصول إلى Native، من دون كشف بيانات أو مفاتيح مستخدم آخر.

## 1. التصميم المعماري المعتمد

### مسار OpenCode الوحيد
**Browser / Gateway UI → Nginx → OpenCode Native → Nginx → Browser**

- نفس واجهة المنصة الحالية، مع العربية RTL والإنجليزية، تعرض الوظائف الأصلية التي يقدمها OpenCode Native.
- **Nginx:** نقطة الدخول والتوجيه، وتمرير HTTP وSSE وفق المسارات الأصلية؛ لا ينفذ AI ولا يُنشئ حالة محادثة.
- **OpenCode Native:** جميع خدمات AI، المزودين والنماذج، إعداداتها واعتماداتها، الجلسات والرسائل والأحداث والأدوات ومحتوى المشاريع الذي يعالجه.
- لا مسار وسيط للاكتشاف أو إنشاء الجلسات أو اختيار النموذج أو إرسال الرسائل أو الاستجابة أو المرفقات.
- لا نظام Chat أو Sessions أو Provider Registry أو Model Catalog موازٍ؛ لا تشغيل محرك إضافي لكل مشروع.
- أي واجهة أو لوحة تتعلق بـOpenCode تعرض الحالة التي يعيدها Native بنفسه، ولا تختلق اتصالًا أو ردًا أو موافقة.

### مسار إدارة المنصة — منفصل تمامًا
**Browser / Gateway UI → Nginx → Platform Administration → Platform Database**

- تسجيل الحسابات وتسجيل الدخول والخروج، الأدوار، صلاحيات المنصة العامة، والتحقق من البريد واستعادة الحساب.
- ملكية المشاريع ومساحات العمل **كبيانات إدارية**، العضويات والمستخدمون، GitHub الخاص بربط الحسابات والمستودعات إداريًا، والفوترة والخطط وملكية الملفات الإدارية وحصص التخزين.
- لا يملك هذا المسار صلاحية فحص أو تعديل أي حالة تشغيل داخل OpenCode.
- ملفات المشاريع الإدارية تختلف عن مرفقات محادثات OpenCode التي يديرها المحرك الأصلي.

### شرط الأمان قبل تعدد المستخدمين
- ممنوع كشف Native API الخام أو مفاتيح مزودي AI أو جلسات الآخرين عبر الشبكة.
- يجب أن يُطبَّق عزل حقيقي للمستخدم ومساحة العمل على مسارات Native **من دون إعادة أي طلب OpenCode إلى مسار الإدارة**.
- لا يكفي HTTP Basic Auth واحد مشترك أو فحص Host Header لإثبات فصل حسابات متعددة.
- إذا كانت آليات Native الرسمية المتاحة لا توفر العزل المطلوب، تبقى إتاحة OpenCode لمستخدمين متعددين **BLOCKED** حتى توفير طبقة وصول/عزل آمنة ومستقلة عن مسار الإدارة؛ لا تُلغَ الحماية لتسريع التطوير.
- لا نسخ أو إظهار أسرار Native في المتصفح، ولا مسح مخزنه أو اعتمادات مشتركة أثناء التجارب.

## 2. خدمات OpenCode Native — جرد رسمي يجب استخدامه مباشرة

**المرجع:** الوثائق الرسمية لـOpenCode Server وConfig وProviders وAgents وTools وPermissions. أسماء المسارات أمثلة موثقة؛ يُعتمد العقد الفعلي الذي تعلنه نسخة Native المثبتة عبر \`/doc\` عند التنفيذ. لا تفترض أن كل خاصية متاحة في كل إصدار.

| المجال | الوظائف الأصلية الواجب توفيرها في واجهة المشروع | أمثلة API أصلية |
|---|---|---|
| صحة الخادم والأحداث العامة | Health/Version، بث أحداث عالمي | \`GET /global/health\`، \`GET /global/event\` |
| مشروع OpenCode الحالي | قراءة المشروعات التشغيلية والسياق الحالي | \`GET /project\`، \`GET /project/current\` |
| المسارات والتحكم بالإصدارات | مسار المشروع، حالة VCS | \`GET /path\`، \`GET /vcs\` |
| تكوين OpenCode | عرض وتحديث إعدادات المحرك وفق صلاحياته | \`GET /config\`، \`PATCH /config\` |
| مزودو AI | اكتشاف المزودين وحالة الاتصال وطرق الاعتماد | \`GET /provider\`، \`GET /provider/auth\` |
| النماذج | قائمة النماذج الافتراضية والمتاحة وحل معرفاتها | \`GET /config/providers\`، وكتالوج Native |
| المصادقة الخاصة بالمزود | حفظ اعتماد مزود من خلال Native، وOAuth حيث يدعم المزود | \`PUT /auth/:id\`، \`POST /provider/{id}/oauth/authorize\`، \`POST /provider/{id}/oauth/callback\` |
| الوكلاء | Build وPlan والوكلاء الفرعيون والوكلاء المخصصون وإعداداتهم | \`GET /agent\`، إعداد \`agent\` الأصلي |
| الجلسات | عرض/إنشاء/قراءة/تسمية/حذف الجلسة، الجلسات الفرعية والحالة | \`GET/POST /session\`، \`GET/PATCH/DELETE /session/:id\`، \`GET /session/status\`، \`GET /session/:id/children\` |
| المحادثات والرسائل | عرض التاريخ وأجزاء الرسالة، إرسال متزامن وغير متزامن | \`GET/POST /session/:id/message\`، \`GET /session/:id/message/:messageID\`، \`POST /session/:id/prompt_async\` |
| الأوامر والتنفيذ | أوامر Slash، أوامر shell ضمن صلاحيات Native | \`GET /command\`، \`POST /session/:id/command\`، \`POST /session/:id/shell\` |
| إدارة دورة الجلسة | Fork، Abort، Share/Unshare، Summarize، Revert/Unrevert، Diff | \`/session/:id/fork\`، \`/abort\`، \`/share\`، \`/summarize\`، \`/revert\`، \`/unrevert\`، \`/diff\` |
| Todo | عرض مهام الجلسة وتحديثاتها الأصلية أثناء عمل الوكيل | \`GET /session/:id/todo\`، أحداث Native |
| Events / SSE | ردود Streaming، تقدم الأدوات، أخطاء التنفيذ، الحالة وإعادة الاتصال | \`GET /event\`، \`GET /global/event\` |
| الأدوات | Bash وRead وEdit وWrite وGlob وGrep وList وTask وWebFetch وغيرها حسب النسخة | أدوات Native وإعداد \`permission\`؛ \`GET /experimental/tool/ids\` و\`GET /experimental/tool\` إذا كانت متاحة |
| الأذونات والأسئلة | طلبات Ask/Allow/Deny، الموافقات والأسئلة التفاعلية، حفظ القرار وفق Native | Permission/Question Native API والأحداث؛ \`POST /session/:id/permissions/:permissionID\` حيث تدعمه النسخة |
| الملفات والبحث | قراءة الملفات وعرض الحالة والبحث بالاسم والنص والرموز | \`GET /file\`، \`/file/content\`، \`/file/status\`، \`/find\`، \`/find/file\`، \`/find/symbol\` |
| المرفقات والوسائط | إدراج FilePart والصور والنصوص وPDF وفق دعم النموذج وNative | Message Parts وFilePart الأصلية؛ لا قارئ أو محرك مرفقات بديل |
| LSP/Formatters | معلومات خوادم اللغة وأدوات التنسيق | \`GET /lsp\`، \`GET /formatter\` |
| MCP | حالة خوادم MCP وإضافتها بما تدعمه نسخة المحرك | \`GET /mcp\`، \`POST /mcp\` |
| Plugins / Skills / Custom Tools | إعداد الإضافات والمهارات والأدوات المخصصة عبر آليات OpenCode | ملفات \`.opencode/\` وإعدادات \`plugin\`، والأوامر الرسمية للنسخة |
| تعليمات المشروع | قواعد الوكلاء والتعليمات ومراجعة تغييرات المشروع | \`AGENTS.md\` و\`instructions\` وإعدادات OpenCode |
| Logs / Diagnostics | سجلات المحرك ومراقبة الأخطاء الأصلية | \`POST /log\` حيث يدعمه Native، وسجلاته المحلية |
| Client / TUI | واجهة تحكم اختيارية للعميل الأصلي | \`/tui/*\` في API الرسمي، إن استُخدمت |
| مواصفات API | اكتشاف التعاقد الحقيقي والأنواع المدعومة | \`GET /doc\` (OpenAPI) |

**قواعد استخدام الخدمات:**
- يستمد اختيار Provider وModel وAgent **من Native وحده**، ولا يُنشأ نموذج موازٍ لتصحيح مشكلة معرف.
- عند \`prompt_async\`، لا يعني HTTP 204 نجاح الرد؛ النجاح وصول Message/Parts وAssistant response حقيقية وتحديث SSE.
- حذف مفتاح مزود أو إعادة ربطه يخضع لطريقة Native التي تؤكدها النسخة المثبتة؛ لا تُحذف مفاتيح مشتركة أو أسرار مستخدمين.
- مشاركة الجلسات أو إتاحتها عبر روابط لا تبدأ تلقائيًا؛ تُضبط وفق صلاحيات Native وأمان المستخدم.
- الملفات والمرفقات تُرسل عبر واجهة Native الرسمية؛ الاستجابة الفعلية تتوقف على قدرات النموذج.
- الأدوات والأسئلة والموافقات يجب أن تكون **حقيقية وقابلة للتفاعل**؛ لا تُعرض بطاقات شكلية.

## 3. تجربة المستخدم والتنقل

- عند تسجيل الدخول الجديد، افتح وجهة البداية المعتمدة للعميل.
- Refresh يعيد **نفس الصفحة**، ونفس Project/Workspace/Conversation حيث تسمح الصلاحيات.
- الانتقال من محادثة إلى أخرى أو من مشروع إلى آخر مباشر، دون العودة إلى Workspace كصفحة وسيطة.
- دعم روابط الصفحات المباشرة وBack/Forward، ومنع إرجاع رد قديم إلى محادثة جديدة بعد التبديل السريع.
- الحفاظ على الرد الجاري وSSE وحالة Pending/Idle/Abort ورسائل الخطأ، دون تكرار جلسات أو فقد الرسائل.
- لا تعيد جلب فهرس مزودين ضخم مع كل رسالة أو تنقل؛ حسن عرض البيانات الوصفية في العميل دون إنشاء مصدر حقيقة بديل.
- عند انتهاء جلسة **المنصة**، أعد المصادقة ثم استعد وجهة المستخدم المصرح بها، ولا تعتبر Refresh تسجيل دخول جديدًا.

## 4. الحسابات والخدمات الإدارية المستقلة

- تسجيل جديد: Full Name وUsername وEmail وPassword وConfirm Password منفصلة.
- الحساب Pending حتى إثبات ملكية البريد. رمز مؤقت لمدة 60 ثانية، مهلة إعادة إرسال 60 ثانية، مع تعديل البريد وإلغاء التسجيل واستئناف الطلب المعلق بصورة آمنة.
- استعادة الحساب: Username وEmail يطابقان السجل نفسه، ورسالة عامة لا تكشف وجود الحساب، ثم إثبات امتلاك البريد برابط/رمز أحادي الاستخدام قبل أي تغيير حساس.
- لا يغيّر إرسال OTP وحده حالة الحساب أو كلمة المرور، ولا يفعّل حسابًا آخر.

### الحالة الحالية للتسجيل والتحقق — نتائج LOCAL المبلَّغ عنها من DeepSeek
- **PASS وفق تقرير Playwright:** إنشاء تسجيل تجريبي عبر واجهة LOCAL أعاد HTTP 201 وحالة `pending_verification`؛ السجل في `pending_registrations` فقط، دون إنشاء مستخدم في `users` قبل التحقق.
- **PASS وفق تقرير Playwright:** محاولة تسجيل الدخول مباشرة بالبريد وكلمة المرور قبل تأكيد الرمز أعادت HTTP 401 و`Invalid credentials`؛ لا يوجد تجاوز للتفعيل في هذا المسار.
- **حاجز إضافي في الشيفرة حسب التقرير:** تسجيل الدخول يرفض حالة `pending_email` وأي حالة غير `active`؛ إنشاء مستخدم من مسودة التسجيل يقع في `registration_drafts.finish()` بعد إدخال OTP صحيح، ويكون الحساب `active`.
- **PASS وفق التقرير:** اكتملت دورة OTP الفعلية لحساب تجريبي واحد على LOCAL؛ توجد حسابات `seed` أُنشئت مباشرة في قاعدة البيانات ولا يجوز نسبتها إلى دورة التسجيل أو اعتبارها دليلًا على تخطي التحقق في واجهة التسجيل.
- **PASS جزئي:** إرسال رمز التحقق إلى البريد الذي يكتبه كل متقدم بصورة ديناميكية؛ أفاد التقرير بوجود أربع مسودات مستقلة لعناوين مختلفة. استجابة مزود البريد بالقبول لا تثبت وصول كل رسالة إلى صندوق البريد أو استكمال كل تسجيل.
- **أُنجز محليًا حسب تقرير DeepSeek، ويحتاج إدراجه في الكود المشترك لاحقًا:** إضافة `POST /api/auth/pending/resend-code` وعرض شاشة إدخال الرمز عند `EMAIL_PENDING` بدل الاكتفاء بالتحذير. حالات `EMAIL_ACTIVE` و`EMAIL_ARCHIVED` تُوجَّه لاستعادة الحساب/إعادة تفعيله؛ رسائل `EMAIL_ACTIVE` و`EMAIL_PENDING` و`EMAIL_ARCHIVED` و`EMAIL_SUSPENDED` و`USERNAME_TAKEN` و`PHONE_TAKEN` أصبحت مميزة ومترجمة بالعربية والإنجليزية.
- **سلامة البناء حسب التقرير:** تحميل خدمة الإدارة دون خطأ، 241 مسارًا مسجلًا، نجاح `node --check app.js` وإعادة تشغيل البوابة محليًا. هذه ليست بديلًا عن اختبارات الرحلة الكاملة.
- **حدود الإثبات والنشر:** ما سبق نُقل من تقرير DeepSeek وليس نتيجة اختبار مستقل هنا؛ التغييرات البرمجية **LOCAL فقط ولم تُرفع إلى المستودع**. لا تعتبر نسختا `updates` و`master` محتويتين تلقائيًا على إصلاحات LOCAL.

- إدارة العملاء والمشاريع وعضوياتها وحصص التخزين والفوترة والخطط ووسائل الدفع وGitHub الإداري، مع إبقاء وظائف OpenCode منفصلة تمامًا.
- خطط المنتج المعتمدة: Trial (مجاني، 30 يومًا، 50 MB)، و\`gateway_100\` ($2، 30 يومًا، 100 MB)، و\`gateway_150\` ($3، 30 يومًا، 150 MB)، و\`gateway_250\` ($5، 30 يومًا، 250 MB). إدارة الأسعار والمدة والسعة ديناميكية دون إتلاف سجلات الاشتراك التاريخية.
- تكاملات الدفع لا تُعلن مفعلة قبل اختبارها، ولا تستخدم دفعات حقيقية للتجارب.

## 5. بيئة التطوير المحلية

- نقطة استخدام المستخدم الرسمية: \`http://localhost:8080\` عبر Nginx.
- خدمة الإدارة الخلفية على \`127.0.0.1:8180\` تظل داخلية، ولا تستخدم كباب ثانٍ للمستخدم. وجودها ضروري لخدمات الإدارة؛ لا توقفها لمجرد أن واجهتها كانت قابلة للفتح محليًا. فحص Host Header وحده ليس آلية ثقة كافية.
- تُستخدم خدمة OpenCode Native المثبتة على الجهاز دون إنشاء محرك جديد. تضبط مسارات Native والـSSE عبر Nginx وتستمد منافذ المحرك الحقيقية من البيئة الجارية، دون تخمين أو تغيير منافذ عشوائي.
- شغّل Nginx من موقع ثابت لا يتأثر بتنظيف مجلد Temp، مع بقاء التكوين الحالي محفوظًا وخطة تراجع آمنة.
- لا تغيير للكود أو الخدمات خارج LOCAL قبل قرار صريح مستقل، ولا دمج تغييرات برمجية غير مراجعة.
