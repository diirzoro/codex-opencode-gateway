# OpenCode Gateway — المذكرة التنفيذية الرسمية الوحيدة
**قرار المالك النهائي — 4 نوفمبر 2026 | نطاق التطوير البرمجي: Windows LOCAL فقط | حالة هذا الملف: توثيق، لا نشر**

> **ممنوع منعًا باتًا تدخل Python Gateway في أي خدمة تخص OpenCode، ولو كان التدخل قراءة أو تحققًا أو صيانة أو تفويضًا لطلب Native.** لا يوجد استثناء بعنوان «التحقق فقط» أو «تحكم إداري» أو «ليس AI inference». هذه قاعدة ملزمة لجميع الإصلاحات اللاحقة وتنسخ أي قرار قديم متعارض.

## 1. حدود الأنظمة — فصل مطلق وواضح

### OpenCode Native وحده — جميع خدمات OpenCode بلا استثناء
- Providers، النماذج والكتالوج وتحديثه والتحقق من معرف النموذج، Model Variants، Agents وإعداداتهم، API Keys وOAuth الخاصان بالمزودين.
- إنشاء/فتح/حذف/استعادة Native Sessions، Conversations، الرسائل والردود والتاريخ والحفظ وإيقاف/إلغاء التنفيذ.
- Prompt وprompt_async والرد الحقيقي، SSE/Streaming/Reconnect، Tools (Shell/Read/Write/Edit)، Todo، Questions، Permissions والموافقات.
- إعدادات المحرك الأصلي، Native Workspaces التنفيذية، ملفات ومرفقات المحادثة وFilePart ومعالجة الوسائط التي يدعمها النموذج.
- بيانات OpenCode الأصلية وذاكرته وإعدادات HOME/XDG وopencode.db وauth.json؛ لا SQL خارجي مباشر على قاعدة Native ولا مخزن موازٍ.

**محظور نهائيًا داخل Python Gateway لأي سبب:** قراءة فهرس /provider أو /agent أو حالة Session/Model لتقرير صلاحية التنفيذ؛ \`require_model\` و\`_authorize_native\` لمسارات OpenCode؛ Python-issued \`X-Accel-Redirect\` كشرط قبل أي Native operation؛ تمرير prompts أو responses أو SSE أو إرسال FilePart الخاص بالمحادثة؛ AI/chat proxy/bridge؛ إدارة أو صيانة Native catalog بـ subprocess (بما في ذلك \`opencode models --refresh\`)؛ تخزين مفاتيح المزودين، أو نماذج المحادثات/الرسائل، أو سجل AI موازٍ. **حتى قراءة الحالة «للتأكد فقط» ممنوعة.** المسارات الموجودة بهذه الوظائف **مخالفات مفتوحة للتصحيح** وليست خدمات مسموحة.

### Python Gateway — شؤون المنصة الإدارية فقط
- Register/Login/Logout/Email Verification/Password Recovery.
- Users، Roles، الحسابات الإدارية والاشتراكات والفوترة والخطط والمدفوعات.
- Project Ownership وWorkspace **metadata الإدارية فقط** وربط المشاريع بالمستخدمين، وGitHub account/repository linking الإداري.
- إدارة بيانات الملفات الإدارية الخاصة بالمشروع، ملكيتها، المخصصات وحصص التخزين؛ وليس رفع/قراءة/تشغيل مرفقات محادثات Native.
- PostgreSQL تخص بيانات المنصة الإدارية فقط، ولا تُستخدم مصدرًا لأي حالة تشغيلية تخص OpenCode.

### Nginx — توجيه مباشر، وليس محرك AI
- **خدمات OpenCode:** Browser → Nginx → OpenCode Native → Nginx → Browser.
- **خدمات إدارة المنصة:** Browser → Nginx → Python Gateway → PostgreSQL.
- **لا يُرسل أي طلب Native إلى Python أولًا** لا للتحقق ولا لإصدار X-Accel-Redirect ولا لتعديل الطلب أو الرد. Nginx لا ينفذ AI بنفسه.
- يحتفظ التطبيق بواجهة Gateway الحالية مع العربية RTL والإنجليزية؛ لا تُنسخ واجهة OpenCode Web ولا يُبنى محرك مستقل لكل مشروع.

### شرط أمان لا يُتنازل عنه
فصل Python عن OpenCode **لا يعني** السماح بوصول مستخدم إلى Native sessions أو ملفات أو مفاتيح مستخدم آخر. يجب اعتماد وسيلة عزل/تفويض حقيقية خارج Python في **مسار خدمات OpenCode**، مع ضمان حماية الاعتمادات وعدم تعريض Native الخام للشبكة. إذا كانت نسخة OpenCode المحلية تتشارك auth.json أو الجلسات بين المستخدمين ولم يثبت العزل، تبقى إتاحة الخدمة متعددة المستخدمين **BLOCKED** حتى وجود حل آمن متوافق مع الفصل المطلق؛ **لا يُعالج ذلك بإرجاع Python إلى مسار Native**. تظل مصادقة Gateway لازمة لوظائف المنصة الإدارية.

## 2. البنية والبيئات المعروفة — وصف لا يجيز تغييرًا
- وفق تقرير LOCAL السابق: مدخل المتصفح Nginx \`8080\`؛ Python Gateway داخليًا \`127.0.0.1:8180\`؛ مسارات Native الداخلية \`19097/19098\`؛ OpenCode Desktop Native \`127.0.0.1:61339\`. تُقاس القيم الفعلية محليًا ولا تُخلط بمنافذ VPS.
- مدخل المستخدم الاعتيادي هو \`8080\`. بقاء \`8180\` كخدمة backend لازمة للتوجيه طبيعي، لكن لا يُستخدم عنوانًا مستقلًا للمستخدم ولا بابًا لتجاوز Nginx؛ لا توقف Gateway ولا تغيّر منافذ دون سبب مثبت.
- تشغيل Nginx من \`C:\Users\user\AppData\Local\Temp\opencode\nginx-1.26.3\` خطر استمرارية وفق التقرير؛ تثبيت موقع ثابت آمن بعد فحص الاعتماديات وبتغيير LOCAL قابل للرجوع، دون خدمة ثانية.
- TEST تاريخيًا: \`test.opencode-gateway.codes\`، Gateway \`127.0.0.1:8001\` وPostgreSQL \`opencode_gateway_test\`؛ LIVE: \`opencode-gateway.codes\`، Gateway \`127.0.0.1:8000\` وPostgreSQL \`opencode_gateway\`. نسخة VPS سُجّل فيها Native \`127.0.0.2:4097\` مع مساري Nginx \`18097/18098\`. هذه معلومات تاريخية مرجعية وليست تعليمات نشر.
- لا تعديل برمجي خارج Windows LOCAL الآن. لا دفع أو دمج للكود ولا تغيير لأي خدمات خارج بيئة LOCAL حتى موافقة صريحة مستقلة.

## 3. حالة الأعمال — ما نُفذ وما لم يكتمل
**كل PASS أدناه «حسب تقارير DeepSeek» ما لم تُرفق أدلة قبول مستقلة؛ لا تُخلط نتيجة HTTP بنجاح AI.**

| المجال | آخر حالة مبلّغ عنها | المطلوب المتبقي |
|---|---|---|
| فصل Native وPython | **غير مكتمل — NONCOMPLIANT**: لا inference/StreamingResponse من Python حسب grep، لكن بقيت قراءة \`/provider\` عبر \`require_model\`، وتدخل \`_authorize_native\` وPython-issued \`X-Accel-Redirect\`، وصيانة catalog من Python | إزالة **كل** تدخل Python في Native مع إبقاء العزل والوصول الآمن خارج Python |
| Login المدير | PASS حسب تقرير LOCAL بعد تعديل اسم المستخدم في قاعدة محلية؛ HTTP 200 بدور admin | الحفاظ على الأمان وتغيير بيانات اعتماد الاختبار المعروفة قبل الإتاحة؛ لا تُخزّن كلمات المرور في هذه المذكرة |
| إنشاء مشروع | PASS مبلغ عنه: فتح نحو 5ms وإنشاء HTTP 201 نحو 17ms | إعادة اختبار بعد إصلاح التنقل، وحفظ الملفات والمشاريع |

| LOCAL 8080/8180 وNginx | يعمل كبنية ذات منفذين بحسب التقرير، لكن باب 8180 المحلي يظهر الواجهة أيضًا، وNginx داخل Temp | اعتماد 8080 كواجهة المستخدم، إبقاء 8180 داخليًا، حماية مسارات Native واستقرار موقع Nginx |
| التسجيل وResend | BLOCKED في الإرسال الحقيقي: \`EMAIL_VERIFICATION_REQUIRED=false\`، لا مفتاح Resend صالح حسب التقرير | Full Name منفصل عن Username، حساب Pending حتى إثبات البريد، OTP لمدة 60 ثانية، resend/edit/cancel، اختبار وصول بريد حقيقي عند توافر الإعداد |
| استعادة الحساب | لم تُقبل بعد: طلب البريد وحده | Username+Email مرتبطان بنفس الحساب، رسالة لا تكشف وجود الحساب، ثم إثبات بريد فعلي قبل تغيير كلمة السر؛ لا تفعيل/تعطيل حساب بمجرد إرسال رمز |

| TEST/LIVE | لم تُنشر إصلاحات LOCAL الجديدة | لا نشر تلقائي؛ موافقة المالك أولًا |

### ملاحظات فنية مؤرخة لا تُعد إذنًا لتصميم مخالف
- تجربة \`modelID=deepseek-v4-pro\` أعادت \`deepseek/deepseek-v4-pro\` في نص الخطأ؛ وضع البادئة داخل \`modelID\` أعاد \`deepseek/deepseek/deepseek-v4-pro\`. تشخيص السبب النهائي يجب أن يكون من OpenCode Native نفسه. لا تحديث للفهرس من Python ولا افتراض أن رسالة الخطأ تثبت وحدها فساد الفهرس.
- فحص DeepSeek الساكن لم يجد inference أو SSE streaming داخل Python؛ **هذا ليس إثبات الالتزام بالفصل الكامل**. وجود تفويض Python أو قراءة Native من Python عند أي طلب يظل مخالفة.
- ملاحظة تاريخية: \`backend/app/services/chat_attachments.py\` أصلح محليًا للتعامل مع Windows بدل \`fcntl\`، وفحوص الملفات الإدارية انتقلت من 500 إلى 200 حسب تقرير سابق؛ لا يمنح ذلك Python حق معالجة مرفقات Native.
- TEST التاريخي نجحت له بعض اختبارات CI دون إثبات رد نموذج حقيقي؛ لا تُسجّل تلك النتائج PASS لرحلة AI.

## 4. قائمة العمل LOCAL حسب الأولوية
1. **الفصل المطلق:** استبدال كل مسارات Native التي تدخل Python بمسارات مباشرة وآمنة عبر Nginx؛ إزالة \`require_model\` و\`_authorize_native\` و\`native_sessions.py\` كوسطاء تشغيليين، وصيانة Native من Python. **لا فتح لـNative لمستخدمين آخرين، ولا تجاوز العزل؛ إذا تعذر ذلك يبقى فتح الوصول متعدد المستخدمين BLOCKED.**
2. حل Model Not Found **داخل Native الأصلي** وإثبات رد حقيقي؛ لا تغييرات على Python لتعديل نماذج OpenCode.
3. إصلاح حفظ الوجهة بعد 401، مع بقاء خمول 15 دقيقة والتمييز بين انتهاء الجلسة وLogout الصريح.
4. دورة Native Create/Delete/Recreate، ثم Messages/History/SSE ومنع التكرار.
5. إكمال Refresh للصفحات، والتنقل المباشر بين المحادثات والمشاريع وBack/Forward.
6. أدوات Native، Todo، Permissions، Questions، Agents، Variants، المرفقات، ثم دورة API Key اختبار مستقلة.
7. تدفقات Register/Resend/Password Recovery، ثم قياسات الأداء، ومعالجة موقع Nginx المؤقت وعنوان الواجهة الرسمي.
8. اختبار Playwright فعلي عبر \`http://localhost:8080\` لكل تغيّر، Browser Network/Console وسجلات Native، وتوثيق HTTP والزمن وPASS/FAIL/BLOCKED؛ لا Mock ولا اعتبار HTTP 200/204 دليل رد مساعد.

## 5. قواعد التسجيل والبريد والحسابات — خدمات Python الإدارية حصريًا
- تسجيل حساب جديد: حقول مستقلة Full Name، Username، Email، Password، Confirm Password، ولا يصبح الحساب نشطًا قبل إثبات ملكية البريد.
- تدفق PendingRegistration موجود وفق المراجعة السابقة: \`POST /api/auth/register\`، \`POST /api/auth/registration/confirm\`، \`PATCH /api/auth/registration/update\`، \`POST /api/auth/registration/cancel\`، و\`GET /api/auth/registration/pending\`؛ هذه معلومات مصدر سابقة وليست إثبات E2E.
- OTP مؤقت 60 ثانية، مهلة إعادة إرسال 60 ثانية، تعديل البريد يلغي الرمز السابق، والطلب المعلق يمكن استعادته بآلية لا تكشف حالة الآخرين. عند تأكيد البريد فقط يبدأ الاستحقاق التجريبي؛ منع التكرار في الحساب أو الاستحقاق.
- لا إرسال رمز استعادة لمجرد إدخال عنوان بريد. بعد Username+Email مطابقين لنفس الحساب تُنشأ عملية استعادة مؤقتة وتصل إلى البريد المسجل، ولا يتم تغيير أي كلمة مرور أو حالة الحساب قبل إثبات امتلاك البريد. لا تُمكّن الرسائل العامة من حصر الحسابات؛ تطبيق rate limits.
- مفتاح Resend ودومين الإرسال يجب أن يكونا صالحين لاختبار الوصول الحقيقي؛ لا تسجيل أسرار في المذكرة. إعداد \`EMAIL_VERIFICATION_REQUIRED=false\` يحتاج معالجة قبل قبول التسجيل الفعلي.
