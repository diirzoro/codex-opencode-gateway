# OpenCode Gateway — المذكرة التنفيذية الوحيدة (Native-first / Functionality-first)
**تحديث: 4 نوفمبر 2026** | **التطوير: `updates`** | **المرجع التنفيذي:** [المهمة #47](https://github.com/diirzoro/codex-opencode-gateway/issues/47)

## القرار الحالي: الوظائف والسرعة أولًا، ثم الحماية المتقدمة
- الهدف: نفس **الإمكانات الحقيقية** و**سرعة الاستجابة** لتطبيق OpenCode المحلي، ولكن داخل تصميم Gateway الموجود؛ **لا نستخدم واجهة OpenCode Web** ولا ننسخها.
- ترتيب العمل الإلزامي: **(1) تشغيل محلي مباشر مع Native على loopback → (2) رسالة ورد حقيقي → (3) استكمال كل وظائف Native → (4) اختبار نفس الوظائف على TEST → (5) حماية متقدمة وعزل متعدد المستخدمين قبل LIVE**.
- لا تضيف طبقات مصادقة لكل استدعاء AI، ولا تحميل فهارس كاملة مع كل صفحة، ولا AI proxy أو queue أو retry من Python، ولا محرك منفصل لكل Workspace.
- **مع ذلك** لا نلغي تسجيل الدخول الموجود ولا نفتح منفذ Native أو مخزن المفاتيح المشترك على الإنترنت: التطوير المباشر يكون على جهاز محلي موثوق فقط، وفي TEST العام تبقى طبقة ملكية/جلسة Gateway الأساسية حتى إيجاد مسار تفويض دون Basic Auth ثانٍ. الحماية المتقدمة تتأخر، والحد الأدنى لمنع الوصول غير المصرح لا يُلغى.

## المسؤوليات الثابتة
- **OpenCode Native الأصلي وحده:** provider/model catalog، اعتماد API/OAuth الأصلي، الوكلاء، المحادثات/الرسائل، `prompt_async`، SSE، Todo، أدوات Shell/Read/Write/Edit، الأسئلة/الأذونات، الحفظ، الملفات والوسائط التي يدعمها فعليًا.
- **Gateway Python للإدارة فقط:** تسجيل المستخدمين، الصلاحيات الأساسية وملكية المشروع، الاشتراكات، بيانات المشاريع والملفات المرجعية. لا تخزين فهرس نماذج/محادثات Native ولا تنفيذ AI.
- **التخزين:** `opencode.db` و`auth.json`/إعدادات Native يديرها OpenCode نفسه؛ لا SQL مباشر ولا قاعدة AI موازية. PostgreSQL منفصلة لـGateway LIVE `opencode_gateway` وTEST `opencode_gateway_test` فقط.
- **الواجهة:** نحتفظ بتصميم Gateway وRTL العربية والإنجليزية، ونُظهر كل وظائف Native الأصلية وحالاتها؛ لا ردود وهمية أو أدوات شكلية.

## البنية المؤكدة والبيانات الفعلية
- على VPS: Native `127.0.0.2:4097`، جلسات/SSE `127.0.0.1:18098`، اكتشاف `127.0.0.1:18097`، Gateway TEST `8001` وLIVE `8000`.
- مخزن قاعدة Native التي فتحها المحرك سابقًا: `/var/lib/opencode-native-test/data/opencode/opencode.db`؛ لا تمسّه. V2 وخمس قواعد قديمة مستقلة حُذفت سابقًا من السيرفر.
- فحص Native عبر VPS `41640486579`: 235 مزودًا و8,936 **تعريفًا** في الفهرس، ولا تعني كلها اتصالًا فعالًا. `/config/providers` أعاد `deepseek` بنموذجين و`opencode` بتسعة نماذج مجانية. `auth.json` الفعلي أظهر معرفَي `openai` و`google`، دون إثبات أن مفتاحيهما صالحان؛ لم تُحذفا.
- فشلت تجربتا الرد الحقيقي رغم قبول Native `prompt_async` في `41641711601` و`41642078622`، وأظهرت الثانية `retry`. هذا هو العائق الوظيفي الأول، لا مزيد من طبقات الحماية.
- نسخة TEST نُشرت فيها تعديلات مرور المحادثات عبر `/native-session/{workspace_id}/...` مع فحص CI `41814783679` ناجح؛ لكن لا دليل كافٍ بعد على إجابة نموذج أو نجاح جميع وظائف الأدوات والملفات.
- **المشكلة المتبقية:** `app.js` يطلب من `/native-direct/api/` التي تتطلب HTTP Basic Authentication إضافية في `ops/native-direct/nginx.conf`، وبالتالي قسم Connections ليس جاهزًا. لا إزالة عامة لـBasic مع بقاء API مشتركًا مكشوفًا.

## خطوات التنفيذ والقبول
1. **محلي Windows أولًا:** إعادة استخدام OpenCode المحلي المستمر عبر `127.0.0.1` داخل جهاز المطور فقط، فحص النسخة والمنفذ والإعدادات الحقيقية. قياس فتح Workspace واختيار النموذج ووقت أول رد مقارنة بتطبيق OpenCode المحلي.
2. **الرسالة الأولى:** إنشاء Native session → `prompt_async` → رد مساعد حقيقي → تاريخ الرسائل → SSE فعلي. تشخيص `retry` من خطأ Native والشبكة والحساب دون تخمين. لا يعتبر HTTP 200/204 نجاحًا.
3. **تكافؤ الوظائف:** المزودون، ربط/إزالة الاعتماد، النماذج، الوكلاء والمتغيرات، المتابعات وTodo، أدوات التنفيذ، أسئلة الموافقة، الرسائل والملفات والمرفقات والصور وPDF المدعومة من النموذج. اختبارات عربية وإنجليزية وإعادة التحميل.
4. **الأداء:** منع إعادة استدعاء الفهرس الضخم عند كل فتح، إزالة النداءات المكررة وبطء التفويض المضاف، بث SSE مباشر، قياسات زمنية بالأرقام؛ لا طبقة AI إضافية.
5. **TEST VPS:** نقل الوظائف التي ثبتت محليًا إلى `updates`، إصلاح Basic Auth الثاني في Connections باستعمال الحد الأدنى من جلسة/ملكية Gateway، اختبار من المتصفح، وتوثيق PASS/FAIL/NOT TESTED.
6. **الحماية آخرًا:** بعد ثبوت التشغيل والسرعة، التخطيط لعزل مفاتيح وحسابات Native 1.19.4 المشتركة، التفويض المتقدم، الحدود والضوابط. لا تعدّل أو تحذف مفاتيح مستخدمين آخرين في أثناء التجارب، ولا تمس LIVE و`master`.

## المطلوب من الوكلاء
- **DeepSeek:** التنفيذ على مراحل صغيرة محليًا أولًا، ثم TEST بعد النجاح، دون إعادة بناء التصميم أو إضافة خدمة AI.
- **ChatGPT Work:** **اختبارات E2E حقيقية إلزامية داخل تطبيق TEST بواسطة متصفح Work بعد تسجيل دخول المستخدم**، تشمل ربط المزود التجريبي، اختيار نموذج Native، محادثة حقيقية وردًا فعليًا وSSE، Todo/Tools/Permissions/Questions، رفع الملفات التي يدعمها النموذج، الحذف/الفصل التجريبي، قياس السرعة وإعادة تحميل الجلسة. مراجعة الكود وMock/CI لا تكفي. يجب كتابة PASS/FAIL/BLOCKED/NOT TESTED مع أدلة HTTP وNative ووقت كل خطوة. لا تعرّض مفاتيح المستخدمين ولا تمس LIVE. راجع تفاصيل التنفيذ في GitHub Issue #47.
- **GitHub Issue #47** هو تفاصيل التنفيذ والاختبارات. لا يُعلن اكتمال المهمة إلا بعد رد نموذج حقيقي ونجاح الأدوات/الملفات المطلوبة وتوثيق ذلك.
- **LIVE وmaster دون تغيير** حتى نجاح TEST وموافقة المالك.

## نتيجة تقرير Work الأول ومهمة إعادة الاختبار الفعلي

- التقرير الذي قُدم في 4 نوفمبر 2026 **تدقيق برمجي/سجلات**، لا اختبار قبول من حساب مصادق عليه؛ لم يرسل Work رسالة حقيقية، ولم يربط مزودًا أو يرفع ملفًا من واجهة العميل، ولم يتحقق من Windows المحلي.
- كشف التقرير **تعارضًا وظيفيًا مثبتًا**: حفظ المفتاح من `app.js` مباشرة في Native لا ينشئ سجل ملكية Gateway الذي يطلبه `native_provider_accounts.require_model()` قبل السماح بإرسال رسالة؛ قد يظهر المزود متصلًا ثم تُرفض الرسالة.
- كشف أيضًا أن `require_model()` يطلب `/provider` الكبير مع كل رسالة، وقد يساهم ذلك في البطء؛ يحتاج قياسًا عمليًا وإصلاحًا لا مجرد تخزين نسخة أخرى من الكتالوج.
- فشل اختبار المرفقات الحالي قبل فحص Native بخطأ `ReferenceError: btn is not defined`؛ بينما 37 اختبارًا للواجهة هي Mock وليست إثبات E2E. سجل نشر `41814783679` نجح لكنه تخطى اختبارات المتصفح/Backend.
- الاختبار الملزم التالي: افتح صفحة TEST المصادق عليها عبر **Work Browser**، نفّذ جميع الخطوات وراقب Network وNative من الواجهة إلى الرد والملفات والأدوات، وقدّم أدلة مباشرة. إن كانت جلسة الدخول أو مفتاح اختبار منفصل غير متاح، اذكر `BLOCKED` وسبب العائق، ولا تضع علامة PASS زائفة.
- لا تغييرات في `master` أو LIVE، ولا حذف/استبدال مفاتيح Native المشتركة. **الحماية المتقدمة آخرًا** بعد نجاح الوظائف، مع الإبقاء على حد أدنى لمنع كشف الاعتمادات.
