# OpenCode Gateway — الاتفاق المعماري والتنفيذي الوحيد

> **قرار معتمد ونهائي:** **كل مشروع (Project) يساوي محادثة واحدة فقط، مرتبطة بجلسة OpenCode Native واحدة دائمة (One Project = One Persistent Native Session).** الاسم الوحيد الذي يكتبه المستخدم ويراه هو **اسم المشروع**؛ وهو نفسه اسم المحادثة. **ممنوع** إنشاء عدة محادثات أو جلسات مستقلة للمشروع الواحد، وممنوع قائمة محادثات منفصلة تحت المشروع. هذا شرط لسلوك النظام والبيانات والواجهة والاختبارات، وليس مجرد إخفاء عناصر من الواجهة.
>
> **الفصل الملزم:** منصة الإدارة تملك حسابات المستخدمين وملكية المشاريع وسياقات Workspace وروابط جلساتها الإدارية. يجوز لخدمات المنصة التحقق من الملكية والربط الإداري اعتمادًا على Platform Database فقط، **ولا يجوز لأي خدمة إدارية استقبال أو توجيه أو تفويض أو معالجة طلب OpenCode Native**. جميع عمليات Native تمر **Browser → Nginx → OpenCode Native**. لا استثناء لـPrompts أو SSE أو Tools أو Todo أو Questions أو Permissions أو Providers أو Models أو Agents أو Credentials أو Files أو Attachments أو Native Session CRUD/History/Status.
>
> **العزل مطلوب قبل الإتاحة لعدة مستخدمين:** لا يُعتمد `directory` القادم من المتصفح كإثبات ملكية. لا يُزال حاجز حماية قائم إلا بعد قيام بديل آمن ومختبر؛ تبقى حالة العزل غير المثبتة **BLOCKED** حتى الاختبار.

## 1. نموذج البيانات والواجهة: مشروع واحد = محادثة واحدة

**Project (كيان إداري):** هو العنصر الأساسي الذي ينشئه المستخدم في Dashboard؛ له `project_id` فريد، `name` وحيد ظاهر، مالك، أعضاء مصرح لهم، ارتباط Workspace/مجلد مشروع، و**مرجع واحد ثابت** `native_session_id`. بيانات الملكية والإدارة والربط تخزن في Platform Database.

**Native Session (كيان تشغيل):** جلسة واحدة مرتبطة بكل مشروع، يدير OpenCode Native رسائلها وتاريخها وأحداثها والأدوات والـTodo والأذونات والملفات. لا تنشئ المنصة محرك Chat أو Session Store بديلًا، ولا تصبح Python وسيطًا لعمليات Native.

**Workspace:** سياق تنظيمي/مجلد عمل تتم إدارته من لوحة المنصة؛ **ليس مستوى محادثات إضافيًا ولا يُطلب من المستخدم الانتقال عبره لفتح مشروعه**. يمكن أن تشترك عدة مشاريع في تصنيف تنظيمي، لكن لا يجوز أن يؤدي ذلك لمشاركة جلسة أو تسريب بيانات بينها.

**السلوك الحتمي:**
1. عند إنشاء المشروع يُنشأ الربط مع **جلسة Native واحدة فقط** بطريقة متسلسلة تمنع التكرار؛ يُستعاد الربط الموجود ولا يُستبدل عند إعادة الطلب أو Refresh أو Login.
2. تظهر في Dashboard **قائمة المشاريع فقط**. النقر على المشروع يفتح **محادثته الوحيدة مباشرة** بكل رسائلها وTools وTodo وملفات سياق المشروع؛ لا صفحة وسيطة ولا زر «New Chat» أو «New Session» أو قوائم Chats داخل المشروع.
3. الاسم الظاهر للمحادثة دائمًا هو **اسم المشروع**. إعادة تسمية المشروع تحدث هذا الاسم الواحد في الواجهة وفي عنوان جلسة Native المرتبطة عند الحاجة؛ لا حقل اسم مستقل للمحادثة ولا انقسام أسماء.
4. إرسال رسالة جديدة يضيفها إلى **الجلسة نفسها**. تبديل المشروع يبدّل `project_id` وربط `native_session_id` فقط؛ لا تُنشأ جلسة أخرى.
5. Refresh وBack/Forward وتسجيل الخروج/الدخول واستئناف SSE تعيد المشروع والجلسة نفسيهما، دون محادثات جديدة أو رسائل مكررة أو إرجاع رد لمشروع آخر.
6. إذا فُقد الربط أو كانت الجلسة غير متاحة، **لا تُنشأ جلسة بديلة تلقائيًا عند كل فتح أو Refresh**. تُظهر الواجهة حالة استعادة واضحة، ويتم الإصلاح المقصود بعد التحقق من الربط والملكية، دون نسخ تاريخ محادثة إلى مخزن آخر.
7. لا تعرض Fork أو New Session أو Child Session أو Share بوصفها محادثات جديدة داخل المشروع. إذا احتاج Native داخليًا إلى عمليات تنفيذ فرعية لا تتحول إلى محادثات مستخدم أو مشروع مستقل، ولا تكسر قاعدة الجلسة الرئيسية الواحدة.
8. عند حذف المشروع أو أرشفته، تُدار دورة حياته من Dashboard مع تأكيد واضح وحفظ التاريخ/النسخة الاحتياطية وفق سياسة البيانات؛ لا يُحذف سجل Native أو ملفات المشروع عرضًا. لا يُعاد استخدام ربط الجلسة لمشروع مختلف.
9. **الترحيل من التصميم السابق:** افحص المشاريع التي لها أكثر من جلسة حالية، ولا تحذف أو تدمج تاريخ الجلسات آليًا. اختر الجلسة الرئيسية فقط وفق قاعدة موثقة وقابلة للتحقق، مع حفظ نسخ احتياطية وتقرير الاستثناءات، وإبقاء الجلسات القديمة خارج واجهة المستخدم حتى قرار ترحيل آمن. لا تدّعِ نجاح الترحيل قبل اختبار Playwright فعلي.
10. فرض الربط الواحد يجب أن يكون على مستوى المنطق وقاعدة البيانات، مع آلية منع ازدواج وتزامن؛ **إخفاء أزرار الواجهة وحده لا يكفي**.

## 2. الحدود المعمارية للخدمات

**OpenCode وحده:** Provider/Model/Agent discovery، إعدادات Native واعتمادات مزوديه وOAuth، إرسال Prompts/Messages، SSE/Events، Tools/Commands، Todo، Questions/Permissions، Native Files/Attachments، Session execution/history/status/abort/recovery، MCP/LSP/Skills/Plugins. المصدر الوحيد هو المحرك الأصلي المثبت وإمكاناته الفعلية. Nginx يوجه HTTP/SSE إلى Native دون تنفيذ أو طبقة خدمات موازية.

**Platform Dashboard وحدها:** تسجيل ودخول المستخدمين واستعادتهم والتحقق من البريد، إدارة الحساب والأدوار، ملكية Project وWorkspace وعضوياتهما وربط `project_id ↔ native_session_id` كبيانات إدارية، GitHub الإداري، الخطط والفوترة والملفات والحصص الإدارية. لا تنشئ Dashboard محادثة موازية، ولا تطلب بيانات Native عبر خدمة إدارة وسيطة.

**ممنوع منعًا باتًا أن تتداخل Python في أي خدمة OpenCode Native، ضرورية كانت أو غير ضرورية:** لا تنفذ أو تستعلم أو تمرر أو تتحقق أو تخزن حالة تشغيل مزودين أو نماذج أو وكلاء أو اعتمادات أو جلسات أو رسائل أو ملفات Native أو SSE أو Tools أو Todo أو Questions أو Permissions أو أي Native API، ولا تتوسط حتى عبر `_authorize_native` أو `X-Accel-Redirect` أو fallback. لا توجد فئة مسموحة اسمها «خدمات OpenCode ضرورية في Python».  **يسمح فقط بفحص ملكية المشروع/Workspace/مرجع الجلسة كبيانات إدارية مستقلة**؛ لا يُحوَّل هذا الفحص إلى معالجة لطلب Native.

**حماية الوصول:** يجب أن تكون هوية العميل وعزله في نقطة الوصول إلى Native موثوقين، لا مجرد `directory` أو `session_id` يختاره المتصفح، ولا Basic Auth مشتركًا. أي نقص مثبت في عزل Native يبقى **BLOCKED** ولا يُعامل كنشر متعدد المستخدمين جاهز.

## 3. التعامل مع OpenCode Native والكتالوج

- استخدم النسخة المثبتة وعقد API الفعلي على `/doc`؛ لا تُنشئ تنفيذًا موازيًا لـSessions أو Chat أو Tools أو Todo أو Questions أو Permissions.
- المزودون والنماذج والوكلاء والاعتمادات تُدار داخل Native؛ لا نسخ رئيسي في Platform DB.
- الكتالوج الكامل لا يُنزّل مع كل رسالة أو تنقل أو فتح مشروع. اعتمد بيانات Native وآليات التخزين المؤقت المدعومة؛ التحقق من تحديث كتالوج Native كل **7–14 يومًا** إن كان مدعومًا، وإلا وثّق القيد دون Scheduler أو Registry موازٍ.
- HTTP 200 لواجهات Tools/Todo/Questions/Permissions لا يثبت دورة فعلية؛ وHTTP 204 عند `prompt_async` لا يثبت ردًا ناجحًا. النجاح يتطلب تنفيذًا وأحداثًا ونتائج حقيقية في المتصفح.
- المرفقات TXT/JSON/Images/PDF تعمل عبر Native Message Parts وفق قدرات النموذج/المحرك، لا خدمة مرفقات موازية.

## 4. متطلبات الواجهة وتجربة المستخدم

- مدخل LOCAL الرسمي `http://localhost:8080` عبر Nginx؛ الخدمات الداخلية لا تكون بوابة ثانية للمستخدم.
- واجهة واحدة عربية RTL/إنجليزية لعرض **المشاريع فقط**. لا أقسام متوازية باسم «Conversations / Chats / Sessions» للمشروع، ولا حقول مستقلة لتسمية المحادثة.
- النقر على Project يفتح محادثته نفسها فورًا. تظهر حالة تنفيذ Native وSSE وTodo وTools ورسائل الخطأ بلا تكرار أو انقطاع.
- Refresh وروابط المشاريع المباشرة وBack/Forward واستعادة الصفحة بعد تسجيل الدخول يجب أن تحفظ **المشروع الواحد وجلسته الواحدة**.
- الاختبارات باستخدام Playwright مرئي وحقيقي على LOCAL. لا تعتمد على استجابة HTTP فقط ولا تعتبر غياب اختبار دليلًا على PASS.

## 5. حالة التنفيذ المثبتة والمتبقية — LOCAL فقط

**قاعدة الدليل:** جميع نتائج PASS أدناه هي نتائج أبلغ بها DeepSeek من تنفيذ واختبارات Playwright فعلية على جهاز Windows LOCAL عند `http://localhost:8080`، وليست تحققًا مستقلًا من هذه المحادثة، لأن تعديلات LOCAL البرمجية لم تُرفع. لا يُعد وصول HTTP 200/204 وحده دليلًا على نجاح دورة وظيفة تفاعلية. **المذكرة تميز بين التنفيذ الذي تم الإبلاغ عنه وبين المتطلبات التي لم يثبت إغلاقها**. لا تُكرر ما أُغلق دون خلل Regression موثق.

### ✅ مغلق وفق التقارير والاختبارات المحلية — لا تعِد تنفيذه

| البند | نتيجة التنفيذ والاختبار المبلّغ عنها |
|---|---|
| **الفصل الأساسي عن Python** | أُزيل `/native-session/{ws}/*` وطبقة `transport` و`authorize_native` و`_authorize_native` ووساطة Prompt/Message/Tool/File و`X-Accel-Redirect` القديمة؛ `/native-session/{ws}/session/{id}/message` أعاد 404. جُهز Nginx لتوجيه وظائف Native مباشرة؛ لا يُستنتج من ذلك اكتمال مراجعة **كل** باك إند Python. |
| **استجابة نموذج حقيقية** | اختبار Playwright أعاد مساعدًا فعليًا بكلمات مثل «مرحبا / ok / native / direct» باستخدام `opencode/deepseek-v4.1-flash-free` مع `prompt_async` مباشر. |
| **Read وWrite من أدوات Native** | أداة Read عرضت ملفات Workspace؛ أداة Write أنشأت ملفًا تجريبيًا حقيقيًا على القرص بمحتوى `hello from tool execution`. **Edit لم يثبت بعد**. |
| **Todo الأساسي** | إنشاء ثلاث مهام بحالة pending؛ تحولت مهمة واحدة من pending إلى completed بالفعل. لا يعني ذلك إثبات جميع انتقالات الحالة. |
| **SSE الأساسي وحالة الجلسة** | فتح SSE عبر Native بنوع `text/event-stream`؛ شاهد الاختبار حالة busy → idle. **تتابع أحداث الأدوات وتحديث الواجهة وإعادة اتصال SSE ما زال بحاجة لإثبات منفصل**. |
| **استعادة أساسية بعد Refresh** | بعد Reload بقيت الجلسة وTodo محفوظتين. لا يعني هذا اكتمال Abort/Recovery أو جميع سيناريوهات التنقل. |
| **Provider / Model / Agent discovery** | ظهرت بيانات Native الفعلية (235 مزودًا في فهرس البحث؛ 83 نموذجًا لدى opencode في إحدى التجارب)، ثم صار فتح Connections/Workspace يعتمد على `/config/providers` للمزودين المحفوظين، و`/agent` للوكلاء، دون تنزيل فهرس `/provider` الضخم عند كل دخول. |
| **اعتمادات المزودين والحذف** | حذف Python `DELETE /api/opencode/connections/deepseek` يعيد 404؛ الحذف الفعلي يتم عبر Native `DELETE /native-direct/api/auth/deepseek` ويعيد 200. أُبلغ بأن قاعدة Gateway فيها صفر بيانات اعتماد للمزودين، وأن `/config/providers` يعرض `opencode` فقط عقب الحذف. **لم يظهر تحقق مستقل من أسماء المداخل المتبقية في `auth.json`**. |
| **تحسين السرعة** | Nginx gzip عند طلب فهرس البحث الكامل. القياسات المبلغ عنها: `/config/providers` نحو 30ms، `/agent` نحو 21ms، وفهرس `/provider` المضغوط عند البحث نحو 1s. هذه قياسات LOCAL وليست تعهدات أداء ثابتة. |
| **واجهة مشروع واحد بدل قائمة محادثات** | أُزيل زر Sessions من التنقل؛ قسم Recent Conversations وبحثه من Home؛ تبويب Conversations وأزرار New Conversation/New Session والبحث والفلاتر ومصدر اختيار الجلسات من Workspace؛ لوحة الأدمن المستقلة للجلسات ومسار `/api/admin/sessions` (عاد 404)؛ وزر New Session من HTML. أُضيف «+ New project» إلى مجموعة Workspace بجوار زر GitHub. |
| **منع تكرار إنشاء الجلسة في الحالة المختبرة** | استدعاء `POST sessions` المتكرر أعاد `runtime_id` نفسه بدل إنشاء جلسة إضافية. **ورد في التقرير أن المنع منفذ لكل Workspace؛ المطلوب الحسم بأنه على مستوى Project مهما تعددت Workspaces**. |
| **صون بيانات الجلسات السابقة** | أُبلغ أن صفوف الجلسات التاريخية لم تُحذف؛ الواجهة تختار أحدث جلسة نشطة وتخفي الأخرى. **تثبيت هذا الاختيار في ربط دائم للمشروع لم يثبت بعد**. |
| **إصلاحات المنصة السابقة** | التسجيل المعلق وOTP ورسائل الحالات، Resend، إعدادات البريد، GitHub الإداري بحسب تقارير المرحلة السابقة، إصلاح Origin وCFFI والمفاتيح والواجهات. لا تعِد بناءها بسبب تغيير معمارية المحادثة. |
| **فحوص البناء والواجهة** | Playwright على LOCAL أظهر عدم وجود أخطاء JavaScript جديدة؛ `node --check` نجح للملفات المعدلة، واستيراد Python نجح مع نحو 214 Route بعد التنظيف وفق آخر تقرير. أخطاء خطوط 404 وحالة Workspace منتهية 410 أُبلغ عنها كحالات قائمة غير مرتبطة بالتعديل. |

### 🔴 المتبقي الآن فقط — وفق ترتيب Functionality First

| الأولوية | الحالة | ما يلزم لإغلاقه فعليًا |
|---|---|---|
| 1 | 🔴 **OPEN — فحص الفصل الشامل عن Python** | افحص على **LOCAL الحالي** كل `native_sessions.py` و`workspaces.py` و`admin.py` و`main.py` والخدمات والواجهة وNginx: لا يحق لـPython أن يقرأ أو ينفذ أو يمرر أو يتحقق من أي **عملية OpenCode Native** دون استثناء، حتى لو كان الادعاء أنها خدمة «ضرورية». لا يجوز له Provider/Model/Agent/Credential/Config، Prompt/Message/History، SSE/Event، Tool/Todo/Question/Permission، Native File/Attachment، Session CRUD/Status/Abort/Recovery أو الاتصال بها كوسيط. Python محصور في أعمال Platform الإدارية وبيانات ملكية وربط Project/Workspace/Session في Platform DB دون استدعاء Native. أثبت route inventory + Network/Nginx evidence وأزل التبعيات غير المتوافقة فقط؛ لا تمس وظائف Platform الحقيقية. |
| 2 | 🔴 **OPEN — فرض جلسة واحدة على Project لا Workspace** | أثبت قيدًا دائمًا وفريدًا `project_id ↔ native_session_id` على مستوى مشروع كامل، بما في ذلك مشروع يضم Workspaces متعددة وطلبات متزامنة. ثبت الربط القديم بدل اختيار أحدث جلسة عند كل دخول. اختبر Rename والاسم الواحد وفتح/تبديل المشروع وRefresh وLogout/Login والحفاظ على الملفات والتاريخ. لا تحذف السجلات القديمة أو تدمجها تلقائيًا. |
| 3 | 🔴 **OPEN — الأسئلة والموافقات التفاعلية** | استدعِ سؤال Native حقيقيًا أو Permission prompt من Agent وأظهر بطاقة الاختيارات والإرسال والمتابعة، واختبر Allow/Deny فعليين. لا تحسب GET 200 أو مكونات شكلية PASS. |
| 4 | 🔴 **OPEN — المرفقات** | نفّذ Native round-trip حقيقيًا لملفات TXT وJSON وصورة وPDF حسب قدرة النسخة والنموذج؛ أثبت إرسال الأجزاء والرد على المحتوى في الجلسة الوحيدة، دون Python attachment engine. |
| 5 | 🔴 **OPEN — Abort / Recovery / استمرارية متقدمة** | أوقف تنفيذ Agent أثناء عمله، أثبت انتهاء التنفيذ واستعادة تاريخ المحادثة دون نسخ أو إعادة إرسال غير مقصودة؛ اختبر تتابع أحداث SSE/Tools الحقيقي، Back/Forward وتبديل المشاريع والعودة. |
| 6 | 🔴 **OPEN — أداة Edit وإغلاق دورة Todo الكاملة** | حرّر ملفًا تجريبيًا قائمًا باستخدام أداة Edit من Native وأثبت فرق الملف على القرص؛ اكمل دورة Todo فعلية تتضمن تقدم المهام إلى completed إن كانت مدعومة. |
| 7 | 🔴 **OPEN — فحوص الكتالوج والاعتمادات النهائية** | تحقق من أسماء مداخل `auth.json` **دون عرض قيم الأسرار**؛ تأكد من عدم إعادة تنزيل الكتالوج في كل رسالة/تنقل، وثبت سلوك Cache وتحديث Native كل 7–14 يومًا إذا كان يدعم ذلك؛ وإلا وثق القيد دون Scheduler/Registry موازٍ. لا تعتبر `connected` دليلًا على مفتاح صحيح؛ الخطأ السابق `deepseek/deepseek-v4-pro: Model not found` لا يعاد فتحه ما دام المزود حُذف عمدًا ولم يُطلب ربطه من جديد. |
| 8 | 🔴 **BLOCKED — العزل قبل النشر متعدد المستخدمين** | سبق إثبات إمكانية استهداف Native direct endpoint باستخدام `directory` من المتصفح وSession ID معلوم دون تحقق كافٍ من الملكية. احتفظ بالحالة كقيد أمان منفصل إلى مرحلة Security Hardening النهائية؛ لا تعلن النظام آمنًا أو جاهزًا لعدة مستخدمين، ولا تضعف الحماية القائمة. |

**قاعدة الإغلاق:** لا تترك بندًا PARTIAL إذا أُثبتت دورته الحقيقية؛ اعرض PASS بدليل قابل للتتبع، أو FAIL يصلح ويعاد اختباره، أو BLOCKED مع سبب محدد. أكمل البنود الوظيفية دون تكرار المنجز؛ تبقى الحماية متعددة المستخدمين مرحلة أخيرة مستقلة، **ولا يجوز** الالتفاف على الفصل وإعادة أي خدمة Native إلى Python بحجة الحماية أو الأداء.
