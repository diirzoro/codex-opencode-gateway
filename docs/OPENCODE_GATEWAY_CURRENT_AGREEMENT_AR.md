# OpenCode Gateway — الاتفاق المعماري والتنفيذي الوحيد

> **قرار معتمد ونهائي:** **كل مشروع (Project) يساوي محادثة واحدة فقط، مرتبطة بجلسة OpenCode Native واحدة دائمة (One Project = One Persistent Native Session).** الاسم الوحيد الذي يكتبه المستخدم ويراه هو **اسم المشروع**؛ وهو نفسه اسم المحادثة. **ممنوع** إنشاء عدة محادثات أو جلسات مستقلة للمشروع الواحد، وممنوع قائمة محادثات منفصلة تحت المشروع. هذا شرط لسلوك النظام والبيانات والواجهة والاختبارات، وليس مجرد إخفاء عناصر من الواجهة.
>
> **الفصل الملزم:** منصة الإدارة تملك حسابات المستخدمين وملكية المشاريع وسياقات Workspace وروابط جلساتها الإدارية. يجوز لخدمات المنصة التحقق من الملكية والربط الإداري اعتمادًا على Platform Database فقط، **ولا يجوز لأي خدمة إدارية استقبال أو توجيه أو تفويض أو معالجة طلب OpenCode Native**. جميع عمليات Native تمر **Browser → Nginx → OpenCode Native**. لا استثناء لـPrompts أو SSE أو Tools أو Todo أو Questions أو Permissions أو Providers أو Models أو Agents أو Credentials أو Files أو Attachments أو Native Session CRUD/History/Status.
>
> **العزل مطلوب قبل الإتاحة لعدة مستخدمين:** لا يُعتمد `directory` القادم من المتصفح كإثبات ملكية. لا يُزال حاجز حماية قائم إلا بعد قيام بديل آمن ومختبر؛ تبقى حالة العزل غير المثبتة **BLOCKED** حتى الاختبار.

## 1. نموذج البيانات والواجهة: مشروع واحد = محادثة واحدة

**Project (كيان إداري):** هو العنصر الأساسي الذي ينشئه المستخدم في Dashboard؛ له `project_id` فريد، `name` وحيد ظاهر، مالك، أعضاء مصرح لهم، ارتباط Workspace/مجلد مشروع، و**مرجع واحد ثابت** `native_session_id`. بيانات الملكية والإدارة والربط تخزن في Platform Database.

**Native Session (كيان تشغيل):** جلسة واحدة مرتبطة بكل مشروع، يدير OpenCode Native رسائلها وتاريخها وأحداثها والأدوات والـTodo والأذونات والملفات. لا تنشئ المنصة محرك Chat أو Session Store بديلًا، ولا تصبح Python وسيطًا لعمليات Native.

**Workspace:** سياق تنظيمي/مجلد عمل تتم إدارته من لوحة المنصة؛ **ليس مستوى محادثات إضافيًا ولا يُطلب من المستخدم الانتقال عبره لفتح مشروعه**. يمكن أن تشترك عدة مشاريع في تصنيف تنظيمي، لكن لا يجوز أن يؤدي ذلك لمشاركة جلسة أو تسريب بيانات بينها.

**السلوك الحتمي:**
1. عند إنشاء المشروع يُنشأ الربط مع **جلسة Native واحدة فقط** بطريقة متسلسلة تمنع التكرار؛ يُستعاد الربط الموجود ولا يُستبدل عند إعادة الطلب أو Refresh أو Login.
2. تظهر في Dashboard **قائمة المشاريع فقط**. النقر على المشروع يفتح **محادثته الوحيدة مباشرة** بكل رسائلها وTools وTodo وملفات سياق المشروع؛ لا صفحة وسيطة ولا زر «New Chat» أو «New Session» أو قوائم Chats داخل المشروع.
3. الاسم الظاهر للمحادثة دائمًا هو **اسم المشروع**. إعادة تسمية المشروع تحدث هذا الاسم الواحد في الواجهة وفي عنوان جلسة Native المرتبطة عند الحاجة؛ لا حقل اسم مستقل للمحادثة ولا انقسام أسماء.
4. إرسال رسالة جديدة يضيفها إلى **الجلسة نفسها**. تبديل المشروع يبدّل `project_id` وربط `native_session_id` فقط؛ لا تُنشأ جلسة أخرى.
5. Refresh وBack/Forward وتسجيل الخروج/الدخول واستئناف SSE تعيد المشروع والجلسة نفسيهما، دون محادثات جديدة أو رسائل مكررة أو إرجاع رد لمشروع آخر.
6. إذا فُقد الربط أو كانت الجلسة غير متاحة، **لا تُنشأ جلسة بديلة تلقائيًا عند كل فتح أو Refresh**. تُظهر الواجهة حالة استعادة واضحة، ويتم الإصلاح المقصود بعد التحقق من الربط والملكية، دون نسخ تاريخ محادثة إلى مخزن آخر.
7. لا تعرض Fork أو New Session أو Child Session أو Share بوصفها محادثات جديدة داخل المشروع. إذا احتاج Native داخليًا إلى عمليات تنفيذ فرعية لا تتحول إلى محادثات مستخدم أو مشروع مستقل، ولا تكسر قاعدة الجلسة الرئيسية الواحدة.
8. عند حذف المشروع أو أرشفته، تُدار دورة حياته من Dashboard مع تأكيد واضح وحفظ التاريخ/النسخة الاحتياطية وفق سياسة البيانات؛ لا يُحذف سجل Native أو ملفات المشروع عرضًا. لا يُعاد استخدام ربط الجلسة لمشروع مختلف.
9. **الترحيل من التصميم السابق:** افحص المشاريع التي لها أكثر من جلسة حالية، ولا تحذف أو تدمج تاريخ الجلسات آليًا. اختر الجلسة الرئيسية فقط وفق قاعدة موثقة وقابلة للتحقق، مع حفظ نسخ احتياطية وتقرير الاستثناءات، وإبقاء الجلسات القديمة خارج واجهة المستخدم حتى قرار ترحيل آمن. لا تدّعِ نجاح الترحيل قبل اختبار Playwright فعلي.
10. فرض الربط الواحد يجب أن يكون على مستوى المنطق وقاعدة البيانات، مع آلية منع ازدواج وتزامن؛ **إخفاء أزرار الواجهة وحده لا يكفي**.

## 2. الحدود المعمارية للخدمات

**OpenCode وحده:** Provider/Model/Agent discovery، إعدادات Native واعتمادات مزوديه وOAuth، إرسال Prompts/Messages، SSE/Events، Tools/Commands، Todo، Questions/Permissions، Native Files/Attachments، Session execution/history/status/abort/recovery، MCP/LSP/Skills/Plugins. المصدر الوحيد هو المحرك الأصلي المثبت وإمكاناته الفعلية. Nginx يوجه HTTP/SSE إلى Native دون تنفيذ أو طبقة خدمات موازية.

**Platform Dashboard وحدها:** تسجيل ودخول المستخدمين واستعادتهم والتحقق من البريد، إدارة الحساب والأدوار، ملكية Project وWorkspace وعضوياتهما وربط `project_id ↔ native_session_id` كبيانات إدارية، GitHub الإداري، الخطط والفوترة والملفات والحصص الإدارية. لا تنشئ Dashboard محادثة موازية، ولا تطلب بيانات Native عبر خدمة إدارة وسيطة.

**ممنوع:** `_authorize_native` أو `X-Accel-Redirect` الصادر من خدمة إدارية كشرط لأي Native request؛ Python provider/model/agent catalog أو prompt proxy أو SSE proxy أو tools executor أو session-history reader؛ تعدد مسارات التنفيذ أو النقل الاحتياطي إلى خدمة إدارية. **يسمح فقط بفحص ملكية المشروع/Workspace/مرجع الجلسة كبيانات إدارية مستقلة**؛ لا يُحوَّل هذا الفحص إلى معالجة لطلب Native.

**حماية الوصول:** يجب أن تكون هوية العميل وعزله في نقطة الوصول إلى Native موثوقين، لا مجرد `directory` أو `session_id` يختاره المتصفح، ولا Basic Auth مشتركًا. أي نقص مثبت في عزل Native يبقى **BLOCKED** ولا يُعامل كنشر متعدد المستخدمين جاهز.

## 3. التعامل مع OpenCode Native والكتالوج

- استخدم النسخة المثبتة وعقد API الفعلي على `/doc`؛ لا تُنشئ تنفيذًا موازيًا لـSessions أو Chat أو Tools أو Todo أو Questions أو Permissions.
- المزودون والنماذج والوكلاء والاعتمادات تُدار داخل Native؛ لا نسخ رئيسي في Platform DB.
- الكتالوج الكامل لا يُنزّل مع كل رسالة أو تنقل أو فتح مشروع. اعتمد بيانات Native وآليات التخزين المؤقت المدعومة؛ التحقق من تحديث كتالوج Native كل **7–14 يومًا** إن كان مدعومًا، وإلا وثّق القيد دون Scheduler أو Registry موازٍ.
- HTTP 200 لواجهات Tools/Todo/Questions/Permissions لا يثبت دورة فعلية؛ وHTTP 204 عند `prompt_async` لا يثبت ردًا ناجحًا. النجاح يتطلب تنفيذًا وأحداثًا ونتائج حقيقية في المتصفح.
- المرفقات TXT/JSON/Images/PDF تعمل عبر Native Message Parts وفق قدرات النموذج/المحرك، لا خدمة مرفقات موازية.

## 4. متطلبات الواجهة وتجربة المستخدم

- مدخل LOCAL الرسمي `http://localhost:8080` عبر Nginx؛ الخدمات الداخلية لا تكون بوابة ثانية للمستخدم.
- واجهة واحدة عربية RTL/إنجليزية لعرض **المشاريع فقط**. لا أقسام متوازية باسم «Conversations / Chats / Sessions» للمشروع، ولا حقول مستقلة لتسمية المحادثة.
- النقر على Project يفتح محادثته نفسها فورًا. تظهر حالة تنفيذ Native وSSE وTodo وTools ورسائل الخطأ بلا تكرار أو انقطاع.
- Refresh وروابط المشاريع المباشرة وBack/Forward واستعادة الصفحة بعد تسجيل الدخول يجب أن تحفظ **المشروع الواحد وجلسته الواحدة**.
- الاختبارات باستخدام Playwright مرئي وحقيقي على LOCAL. لا تعتمد على استجابة HTTP فقط ولا تعتبر غياب اختبار دليلًا على PASS.

## 5. حالة الإنجاز الحالية — لا تُعد الأعمال المغلقة

**مغلق وفق تقارير LOCAL السابقة:** التسجيل وحالات OTP ورسائل البريد وResend، إصلاحات Origin وCFFI والواجهات والمفاتيح، تحميل مزودين/نماذج/Agents من Native، إرسال Prompt مباشر وظهور رد نموذج فعلي، قراءة وكتابة ملفات عبر أدوات Native، إنشاء Todo وتحريك حالة عنصر، وعودة الجلسة والـTodo بعد Refresh. هذه نتائج مُبلّغ عنها وليست فحصًا مستقلاً لهذه النسخة من الشيفرة؛ لا تُكرر دون Regression موثقة.

**المطلوب استكماله فقط:**

| الأولوية | الحالة | معيار القبول |
|---|---|---|
| 1 | 🔴 **OPEN — مشروع واحد/جلسة واحدة** | تطبيق وإثبات الربط الدائم الفريد `project_id ↔ native_session_id` والاسم الواحد وعدم ظهور أو إنشاء Chats/Sessions إضافية في Dashboard. اختبار إنشاء/فتح/إعادة تسمية/تبديل/Refresh/تزامن وترحيل المشاريع الحالية دون فقد البيانات. |
| 2 | 🔴 **OPEN — وظائف Native غير المثبتة** | Playwright حقيقي لتنفيذ Edit، Questions/Permissions تفاعلية، أحداث SSE فعلية، Attachments round-trip، Abort/Recovery، واستمرارية الأدوات والرسائل. لا إعادة لاختبارات Read/Write/AI response المنجزة. |
| 3 | 🔴 **OPEN — كتالوج Native** | قياس حجم وتكرار طلبات Provider/Model من المتصفح، وإثبات التخزين والتحديث من Native بما فيه شرط 7–14 يومًا إذا دعمه المحرك. |
| 4 | 🔴 **OPEN — بقايا خدمة الإدارة** | التحقق أن `/api/native-test/*` المتبقي يعيد **ربط وملكية** Project/Workspace/Session فقط من Platform DB، ولا يقرأ أو يعدل بيانات جلسة Native التشغيلية، وأن بقية Native traffic مباشرة عبر Nginx. |
| 5 | 🔴 **BLOCKED — العزل الأمني** | أثبت تقرير LOCAL أن بعض Native direct paths يمكن الوصول إليها عبر `directory` المتحكم فيه من المتصفح. لا اعتماد متعدد المستخدمين حتى إغلاق الوصول غير المصرح به باختبار فعلي. يظل منفصلًا عن قبول الوظائف، ولا تُزال حماية قائمة لفرض الفصل. |

## 6. التنفيذ والتوثيق

- لا تعِد بناء ما ثبت عمله. نفّذ **المتبقي فقط**، ولا تفتح مهام سابقة لمجرد أنها مذكورة.
- لا حذف أو دمج أو تغيير تلقائي لتواريخ محادثات موجودة أو جلسات قديمة دون نسخة احتياطية وخطة ترحيل آمنة.
- التغييرات البرمجية والاختبارات على LOCAL فقط ما لم يصدر قرار نشر صريح. لا Push أو تغييرات TEST/LIVE.
- **هذه هي المذكرة الوحيدة**: `docs/OPENCODE_GATEWAY_CURRENT_AGREEMENT_AR.md`. لا تنشئ مذكرات متعارضة ولا تحفظ تاريخ نسخ قديمة داخلها. حدّث حالة المتطلبات الحالية فقط.
