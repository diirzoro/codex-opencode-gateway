# OpenCode Gateway — الاتفاق التنفيذي الوحيد والحالة الحالية
**تحديث: 4 نوفمبر 2026** · **المستودع:** `diirzoro/codex-opencode-gateway` · **الفرع النشط:** `updates`

## 1. ما نعتمده فقط
1. OpenCode Native المثبت والجاري 24/7 هو **محرك AI الوحيد**: المزودون، النماذج، مفاتيح الاعتماد، اختيار الوكيل، المحادثات، الرسائل، `prompt_async`، SSE، الأدوات، Todo، السؤال، الأذونات، الملفات المدعومة أصلًا وسجلها.
2. لا خدمات AI موازية، ولا Python inference/queue/model registry، ولا قواعد بيانات AI أو كتالوج نماذج خاص بـGateway. تبقى قاعدة `opencode.db` وملفات الاعتماد الأصلية تحت إدارة OpenCode نفسه؛ لا SQL مباشر إليها من Gateway.
3. Python Gateway يبقى فقط للمصادقة والحسابات والاشتراكات والصلاحيات وملكية المشاريع/مسارات الملفات، ولا ينشئ محادثات بديلة أو يستدعي نماذج بنفسه. أي جسر التفويض للمزودين يجب أن يحمي الأسرار ولا يتيح الوصول إلى جلسة مستخدم آخر.
4. يحتفظ المشروع بـPostgreSQL LIVE `opencode_gateway` وTEST `opencode_gateway_test` كلٍّ على حدة؛ هما لبيانات التطبيق لا للتنفيذ AI.
5. مزود OpenCode ونماذجه المجانية الأصلية يظهران مباشرة إذا أعلنهما Native؛ لا ربط API يدوي لمجرد استخدام المزود المجاني. `connected` لا يعني مفتاحًا محفوظًا صالحًا، وقائمة `/config/providers` ليست إثبات اعتماد.
6. Dashboard Connections يعرض قائمة Native الحقيقية ويربط المفاتيح ويزيلها عبر واجهات Native الأصلية **بشرط إثبات فصل الحسابات**. Workspace يستخدم فقط نماذج الحساب المتاحة أو النماذج العامة المجانية ويعمل عبر Native وحده.
7. سرعة التحميل: لا تنزيل للفهرس الكامل عند كل فتح Workspace أو إرسال رسالة؛ استدعاء Native محفوظ والحالة المؤقتة في ذاكرة الواجهة فقط، وتُلغى عند تغيير الحساب أو الاتصال.
8. **TEST أولاً**. لا تغييرات في `master` أو LIVE قبل تقرير قبول حقيقي من متصفح وسيرفر وحسابين.

## 2. بنية السيرفر التي ثبتت سابقًا
- LIVE Gateway `127.0.0.1:8000`؛ TEST Gateway `127.0.0.1:8001`.
- Native الجارية: `127.0.0.2:4097`؛ Nginx discovery `127.0.0.1:18097`؛ sessions/SSE `127.0.0.1:18098`.
- قاعدة OpenCode Native التي ربطها فحص العمليات بمحركه: `/var/lib/opencode-native-test/data/opencode/opencode.db`. مخزن `auth.json` الأصلي يبقى محفوظًا.
- حُذف V2 القديم من Nginx TEST، وحُذفت خمس قواعد `opencode.db` متقاعدة بواسطة مالك السيرفر. لا يجوز حذف قاعدة Native الفعلية.
- حُذفت ملفات محرك Python AI الستة القديمة من `updates` ومسار TEST بتشغيل GitHub Actions الناجح `41636803057`.

## 3. الأدلة — لا نخلط الفهرس بالاتصال الفعلي
- فحص Native المباشر `41640486579`: `GET /provider` و`GET /config/providers` نجحا عبر المحرك الحقيقي؛ 235 مزودًا و8,936 تعريف نموذج في الفهرس، **لا يعني أنها متصلة**.
- ظهرت في `/config/providers` تعريفات `deepseek` (نموذجان) و`opencode` (9 نماذج مجانية). في ملف Native `auth.json` الذي فُحص، معرفا `openai` و`google` فقط، ولم يُثبت نجاح أي مفتاح؛ لم نحذف هذين الاعتمادين.
- في اختباري `41641711601` و`41642078622` قبل Native إنشاء الجلسة ورسالة `prompt_async` لنموذجين مجانيين، **لكن لم يصل رد مساعد**؛ الاختبار الثاني أظهر حالة `retry`، وهي غير مشخَّصة بعد. لا يجوز وصف المحادثة بأنها ناجحة.
- تم نشر تحويل محادثات Workspace إلى `/native-session/{workspace_id}/...`، وفحص نجاح نشر `41814783679`. Gateway يراجع صلاحية الحساب وملكية المشروع ثم Nginx/Native ينقلان الرسالة/التدفق. لا يؤكد CI وحده نجاح تجربة المتصفح.
- **خلل ما زال موجودًا:** `app.js` الخاص بـDashboard Connections يستخدم `/native-direct/api/` المحمي بـHTTP Basic من `ops/native-direct/nginx.conf`. لهذا قد يطلب المتصفح اسم مستخدم/كلمة مرور ثانية. هذا ليس OpenCode Web. لا يجوز إزالة Basic وفتح واجهة Native الخام للمستخدمين.
- **خلل العزل:** الاعتمادات في OpenCode Native 1.19.4 الحالية مشتركة على مستوى عملية المحرك. لم يثبت عزل مفاتيح مستخدمي TEST عن بعضهم أو عن LIVE. تفعيل حذف/استبدال عام قد يؤثر في اعتماد مستخدم آخر. كذلك المسارات الحالية لقراءة metadata عبر Python لا تطابق تمامًا شرط «Native-only في بيانات AI»؛ تحتاج إعادة تصميم آمنة.

## 4. الأعمال الإلزامية قبل السماح بالاستخدام
- إصلاح قسم Connections ليستخدم جلسة Gateway وحقوق الحساب من غير Basic إضافي، ودون تسريب Provider.key/options أو معلومات جلسات أخرى. لا تعرض واجهات `/auth` العامة قبل إثبات فصل الحسابات.
- التحقق عمليًا من تسجيل دخول حسابين مستقلين، والملكية، والمزودين/النماذج الأصلية، والتحقق من المفتاح وOAuth وحذف/تدوير اعتماد تجريبي **دون لمس مفاتيح LIVE**.
- تحديد سبب `retry` والحصول على رد مساعد حقيقي باسم المزود والنموذج المحددين؛ اختبار SSE، إعادة الاتصال، التاريخ، الإيقاف، السؤال، الأذونات، الأدوات وTodo.
- اختبار رفع/قراءة ملفات المشروع والصور وPDF والوسائط الأخرى فقط عندما يعلن Native دعم النموذج للمدخلات؛ لا محاكاة لإرسال المرفقات.
- فحص جميع ملفات الروتس والاستدعاءات ومسارات Nginx، منع V2 وPython AI، التأكد من عدم تكرار الفهرس ومشكلات الصلاحيات وسرعة التحميل، ثم تقرير Pass/Fail/Not Tested.
- تجنب إنشاء أي محرك، خدمة، قاعدة أو منفذ جديد؛ توثيق أي عدم توافق تقني بدل التحايل عليه.
