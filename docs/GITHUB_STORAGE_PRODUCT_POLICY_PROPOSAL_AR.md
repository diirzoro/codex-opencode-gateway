# مقترح سياسة التخزين المنفصل لمشاريع GitHub — 31 أكتوبر 2026

> **مسودة تجارية/تقنية فقط، غير مفعّلة ولا تغير الأسعار أو اشتراكات العملاء أو إعدادات TEST/LIVE.** القرار النهائي للأسعار وتنفيذ الاستحقاقات يتطلب قبول المالك واختبارات.

## الموجود فعليًا في المصدر
- `backend/app/services/workspaces.py`: 50 MiB إجمالية لكل حساب لجميع المشاريع الداخلية (`account_local_storage`)؛ نسخ GitHub المستوردة محدودة تقنيًا بـ512 MiB **لكل Workspace** (`GITHUB_WORKTREE_LIMIT_BYTES`) دون سقف إجمالي لكل حساب وفق اشتراك.
- `GET /api/profile/storage` يرجع إجمالي المشاريع الداخلية فقط، أما `GET /api/workspaces/{id}/storage` فيرجع استخدام Workspace واحد. واجهة `dashboards.js` تعرض استخدام مساحة العمل النشطة؛ قائمة مستودعات GitHub لا تعرض إجمالي الحساب أو المتبقي. لذلك اختلاف العرض بين TEST/LIVE ليس إثباتًا لاختلاف حدود التخزين.
- `backend/app/models/platform.py` يستخدم `subscriptions.plan_id` واحدًا لكل مستخدم؛ لا يمكن بيع اشتراك داخلي واشتراك GitHub مستقلين بأمان قبل فصل الاستحقاق والدفع.
- `backend/app/services/workspace_cache.py`: سياسة النسخ المؤقتة من GitHub 73 ساعة، وملفات المشروع الداخلي 7 أيام؛ لا يجوز حذف المستودع البعيد بسبب حصة Gateway.

- **أسعار وباقات المشاريع الداخلية الحالية لا تتغير**؛ حصة 50 MiB تبقى كما هي حتى قرار منفصل. الاشتراكان مستقلان ومتزامنان، ولا يؤدي شراء باقة GitHub إلى استبدال اشتراك المشروع الداخلي أو إعادة تشغيل التجربة المجانية.
- الحصة تخص ملفات العمل الفعلية المخزنة **على خادم Gateway**، وليست سعة مستودعات GitHub.com أو خدمة Git LFS. لا يشمل السعر رسوم مزودي نماذج AI ولا موارد تشغيل معاينة إضافية.
- الحد **لكل حساب عبر جميع GitHub Workspaces** وليس لكل مستودع؛ العدد التراكمي لا يسمح بتجاوز الحد عن طريق إنشاء نسخ متعددة. المستودعات الأكبر من الحصة تحتاج رفض استيراد واضح قبل التخزين، أو آلية اختيار/تخفيض آمنة.
- احتساب حجم `.git` والملفات المؤقتة يجب تعريفه صراحةً وتنفيذه باتساق؛ لا يجوز إخفاء مساحة مستهلكة فعليًا ثم مفاجأة العميل بالمنع.
- 80% إشعار، 95% تحذير، 100% منع الإضافات التي تتجاوز الحد، مع استمرار القراءة والتصدير والمزامنة الآمنة دون حذف بيانات غير مدفوعة إلى GitHub.
- بعد انتهاء الدفع أو تخفيض الباقة والوجود فوق الحد: فترة قراءة/تصدير آمنة ولا حذف فوري؛ طبّق سياسة صلاحية الكاش والاحتفاظ الحالية بصورة مستقلة، مع حراسة التغييرات غير المحفوظة.

## تغييرات الواجهة/API المطلوبة
1. «المشاريع الداخلية»: المستخدم / الحد / المتبقي على مستوى الحساب.
2. «مشاريع GitHub»: المستخدم إجمالًا / 100 أو 250 أو 500 / المتبقي / نسبة الاستخدام / فئة الاشتراك وتاريخ انتهائها.
3. تحت كل مستودع: مساحة النسخة المحلية منه فقط، دون الخلط مع GitHub البعيد.
4. الأرقام تُحسب على الخادم من الملفات المملوكة للحساب، لا من بيانات ثابتة أو من العميل؛ يجب توحيد العرض بين TEST وLIVE. عند تعذر الحساب اعرض خطأ واضحًا وزر تحديث لا رقم صفر مضلل.

## مسار تنفيذ آمن
1. **قراءة/عرض فقط:** API مستقل لإجمالي استخدام GitHub للحساب، والواجهة التي تعرضه، دون تغيير الحصص الحالية.
2. **فصل المنتجات في الفوترة:** نمذجة `internal` و`github` باشتراكات وPaymentOrders واستحقاقات مستقلة، Migration أمامية تحفظ جميع الصفوف والخطط/الطلبات القديمة، وبدون مزامنة قاعدة TEST مع LIVE.
3. **تطبيق الحدود:** التحقق عند الاستيراد والرفع وعمليات Native، مع تحمّل التزامن بين عدة مساحات ومستخدمين وعدم حذف الملفات تلقائيًا.

5. **خارج النطاق:** تغيير `.github/workflows/**` أو نقل بيانات/مفاتيح/إعدادات دفع بين TEST وLIVE أو تعديل OpenCode Native.
