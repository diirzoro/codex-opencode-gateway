## Source implementation

- `native_sessions.py`: TEST-only platform admission, owned Project/Workspace/native-session map, bounded create/list/read metadata and `X-Accel-Redirect` authorization. Native JSON/SSE responses never enter Python. Directory is derived from the owned filesystem root, not caller headers/query. Native session `directory` must match on every session admission. List results intersect engine state with existing owner mappings; arbitrary engine sessions are never adopted. Missing old files/history are not recreated/deleted. Creation adds only a mapping and a native external-directory deny rule.
- `native-session-client.js`: actual v1.18.32 prompt schema `{model:{providerID,modelID},agent?,variant?,parts}`; native snapshots/events/tools, questions, permissions and Todo displayed through existing UI. Model/agent/variant selection belongs to native engine. Several conversations may exist/work concurrently; no Gateway execution slot/queue/receipt is used. Same-session model/variant choice is restored; switching closes the previous EventSource and rejects stale/foreign-session updates. Continuous SSE renders before completion; slow snapshots serialize instead of starving visible updates. No invented persistent queue/retry guarantee: native errors are shown, no automatic resend.
- Existing runtime adapter selects the native transport only after authenticated TEST state admission; provider/agent reads go directly through Nginx. A fresh native load does not need an existing per-workspace process. Native OpenCode `connected` state is authoritative for models. Provider key/OAuth account migration is not part of these two tasks; no old key is copied to central engine.
- Opt-in native mode rejects legacy Python agent/queue endpoints, prevents `for_workspace`/account-runtime process spawning, and skips the old account credential synchronization sweep. With the flag absent/false, the old path remains available for rollback. It is not deleted before actual TEST acceptance.
- Native file parts use the server-owned file URI base and uploaded relative filename. The gate verifies file scheme, root, existing file and symlink/private-path rules. Models decide content support.
