## 1. Reduce permission interruptions using Native capabilities

Original source inspected via git at anomalyco/opencode v1.19.4, tag148842ef7cb1bc34192b3fff57d0f9721ab9c801: permission/index.ts, tool/read.ts, tool/edit.ts, tool/glob.ts and session/prompt.ts. Public documentation: https://opencode.ai/docs/permissions/ (current docs include newer options; do not assume every option exists in1.19.4).

- Native `allow` is now the default for Todo read/write and asking a Native question, subject to the administrator's enabled-tool allowlist. Questions still wait for the user's actual answer; only the redundant approval to ask is removed. Existing Todo behavior/data/rendering are preserved.
- A single explicit button approves only the currently displayed requests in a same-tool group, using existing Native `once` replies after each Gateway ownership/path/policy check. Newly arriving requests are excluded; failures stop the batch and refresh pending requests. This is a UI batch action, not an execution queue or automatic approval service.
- Exact-file remembering uses Native's existing session permission field and `PATCH /session/{id}`. A small Gateway management endpoint authorizes the mapped owned session and a real pending request, obtains its exact paths from Native metadata and checks actual worktree, ownership, protected files, wildcards, traversal and symlinks. It never accepts browser-supplied role/path/rules. Native stores the grant in that one session. No Python permission database or parallel executor is created.
- UI offers Allow once, Remember these files and Reject. Remember applies to that permission and exact files in later prompts of this conversation, never to another session/workspace or a directory wildcard. Gateway checks saved paths again before each new prompt and drops invalid grants. Native path metadata is read once per validation batch, not once per grant. At most20 files in one decision and100 grants per session.
- Current pending tool still receives original Native `once` through protected Nginx. No AI body or SSE is proxied by Python. Shell, subagents, arbitrary executors, external directories and unknown tools remain denied; protected config/secrets are not eligible for remembered permission.

### Verified API limitations — do not hide these

1. In1.19.4, file tools propose `always:["*"]`; the permission service stores approved rules per Native directory instance and evaluates them after configured policy. Its evaluate function uses last matching rule. Forwarding raw `always` can therefore supersede configured denies and affect other conversations in that instance. Gateway continues rejecting `always`; no blanket auto-approval flag, service restart, original config change or Native cache mutation was used. Pre-existing approved-cache entries are not proved absent or revoked; shared engine must remain untouched. Historical claims that deny always overrides this cache are superseded by this pinned source finding.
2. SessionPrompt.run reads the session before its loop. A permission PATCH while a run is waiting does not establish immediate policy reload in that captured run. UI explicitly says remembered files are for subsequent prompts and the current run may still ask. No claim of eliminating all requests in an ongoing run is made. Live behavior of this patch remains untested.
3. Native permissions match tool and pattern, not diff line count or semantic danger. This patch does not invent a Python risk classifier. New/unremembered file changes and searches still ask. Opting to remember edit permission allows later changes to those exact files, including large changes; it is not a guarantee of an extra prompt for a large rewrite or deletion of an already approved file. Use Allow once when that distinction matters. No broad future-project consent is granted.
